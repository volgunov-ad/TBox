# Менеджер каталога Dashing Store (Windows)

Мини-программа для наполнения sync-папки AppStore на Яндекс.Диске
(зеркало — Mail.ru). Пишет те же файлы, что читает APK `:store`.

## Что нужно

- Windows
- Python 3 с **tkinter** (сборки с [python.org](https://www.python.org/downloads/) —
  галочка «tcl/tk» при установке)
- Локальная папка, которую клиент Диска синхронизирует с
  [AppStore на Яндексе](https://disk.yandex.ru/d/KDaHLxbFtPAjYA)
  (желательно то же дерево копировать на
  [Mail.ru](https://cloud.mail.ru/public/voi3/4Lx1RhqV9))

Зависимостей `pip` нет.

**Обновляйте эту папку `tools\appstore_manager` вместе с репозиторием.** Старая
копия менеджера при сохранении сотрёт `sections` и `downloads` в
`catalog.meta.json` (неизвестные поля dataclass).

## Запуск

Дважды щёлкнуть `Запуск.cmd` в этой папке  
или:

```bat
py -3 tools\appstore_manager\appstore_manager.py
```

## Как пользоваться

1. **Папка AppStore…** — указать корень sync (внутри должны быть
   `release\` и `dev\`, либо сразу `release\apps`).
2. Выбрать канал **release** / **dev**.
3. Слева — список приложений и колонка **«Состояние»** (`ок`, `телефон`
   или красным: нет APK / `version.json` / packageName / проблемы файлов
   карточки); справа — вкладки **Описание**, **Файлы в Загрузки**,
   **Changelog (карточка)**.
4. **Сохранить (Ctrl+S)** — пишет `catalog.meta.json`, оба changelog и
   пересобирает `catalog.json`. При переходе на другое приложение, смене
   канала или закрытии окна с несохранёнными правками менеджер спросит:
   сохранить, отбросить или остаться. **Открыть папку** — папка приложения
   в проводнике.
5. **Заменить APK…** — копирует `.apk` в `apps\<id>\`, спрашивает **flavor**
   (`ru` / `en` / `default`; из имени файла часто угадывается `-ru-` / `-en-`),
   сам читает из APK: `packageName` / `versionCode` / `versionName` / label,
   **cert SHA-256** и по возможности **иконку**. В `version.json` запись этого
   flavor обновляется, APK другого языка **сохраняются** (можно держать оба
   ru и en). Если pin подписи уже был и ключ другой — подтверждение смены.
6. **Иконка…** — ручная замена PNG/WebP/JPEG (если из APK не извлеклось или
   нужна своя). В магазине на ГУ: иконка с Диска, иначе иконка установленного
   приложения, иначе буква названия.
7. **Добавить…** — выберите APK: подставятся package / version / title;
   id можно поправить. «ГУ» — список «A9 и A10» / «Только A9» / «Только A10».
8. Клиент Яндекс.Диска сам унесёт изменения в облако; для Mail.ru —
   скопируйте то же дерево `release\apps` / `dev\apps` **включая**
   `apps\<id>\files\`.

### Поля описания

| Поле | Смысл |
|------|--------|
| id | Стабильный id папки (не меняется) |
| packageName | Пакет Android |
| Название / Издатель / Описание | Витрина |
| ГУ | «A9 и A10» / «Только A9» / «Только A10» → `hu` |
| Куда ставится | «На ГУ» / «На телефон (QR и Загрузки)» → `hu` / `phone` |
| Разделы магазина | Multi-select по разделам канала (кнопка **Разделы…**) |
| cert SHA-256 | Pin подписи из APK |

Поля «Происхождение», «Проверено», «Заметки проверки», «Категория»,
«APK в Загрузки», «Changelog APK» **удалены**.

### Разделы

Кнопка **«Разделы…»** (панель и рядом с multi-select): таблица
«Название | Название EN | Приложений», кнопки Добавить / Изменить / Удалить
(снимает раздел со всех карточек) / Выше / Ниже. Разделы — на уровне канала
(`release` и `dev` независимы). В магазине — чипы фильтра; приложение может
быть в нескольких разделах.

### Файлы в Загрузки

Вкладка **«Файлы в Загрузки»**:

- **Папка в Загрузках** — одно имя папки на карточку (Store пишет в
  `Download/<папка>/`).
- Таблица файлов: имя, размер, SHA-256, состояние (ок / нет файла / изменён).
- **Добавить файлы…** — multi-select; копируются в `apps\<id>\files\`,
  считаются sha256 и размер. При совпадении имени — вопрос «Заменить?».
- **Удалить выбранные…** / **Открыть папку файлов**.

Store при «Получить» / «Обновить» / «Скачать в Загрузки» сохраняет эти файлы
в Загрузки (после проверки sha256). Для DCL Install сюда кладут APK лаунчера
(миграция копирует его один раз из `dcl-launcher`).

### Одноразовая миграция

При **Обновить** / открытии папки менеджер сам переводит старый
`catalog.meta.json`:

- `category` → разделы «Приложения» / «Инструменты» / «Утилиты»;
- `copyApkToDownloadsAppId` → копии APK в `files/` (статичные; после
  обновления источника прикрепите новый файл);
- короткий `changelog` из `version.json` → `changelog.ru.txt` /
  `changelog.en.txt`, если файла ещё нет;
- удаляются `origin`, `verified`, `reviewNotes`, `category`,
  `copyApkToDownloadsAppId`;
- карточки с «Проверено = нет» раньше были скрыты, теперь публикуются —
  сообщение перечисляет их первой строкой; удалите лишние.

Показывается сообщение «Каталог &lt;канал&gt; переведён на новый формат».
Повторный запуск ничего не меняет. CLI:

```bat
python tools\build_apps_catalog.py --apps-dir …\release\apps --migrate --write
```

### Что такое cert SHA-256

Белый список отпечатков подписи в `catalog.json`. На ГУ Store после
скачивания сверяет сертификат APK с этим списком: несовпадение → отказ.
Пустой список = проверка подписи выключена (остаются sha256 файла и
packageName). Менеджер при замене APK **заполняет pin сам**; смена ключа
(другой cert) — только после подтверждения.

Чтение APK: `aapt` / `apksigner` из Android SDK при наличии, иначе разбор
`AndroidManifest.xml` + `keytool` для cert (stdlib / JDK, без pip).

При первом открытии пустой папки подставляется образец
`catalog.meta.json` из репозитория (**Dashing Store**, Monitor, MQTT, camd,
**DCL Launcher** и **DCL Install**). Если `catalog.meta.json` уже есть, но
в нём нет новых seed-id (например `tbox-store`), менеджер **дописывает**
их, не затирая ваши поля. Свежий seed без разделов — в магазине только «Все».

### Changelog на карточке (`changelog.ru.txt` / `changelog.en.txt`)

Во вкладке **«Changelog (карточка)»** — два многострочных поля. Пишутся в
`apps\<id>\changelog.ru.txt` и `changelog.en.txt`. На ГУ Store при открытии
карточки качает файл языка UI магазина (ru/en), иначе второй язык.

Кнопки: **«Сохранить changelog.ru / .en»** или **«Сохранить всё»** (описание +
оба файла + catalog).

### Телефонное приложение (`phone`, installMode=phone)

Карточка `phone` (`vad.dashing.tbox.phone`) с «Куда ставится» =
«На телефон (QR и Загрузки)»:
на ГУ **не** ставится. В магазине — QR на публичную страницу APK (Яндекс /
Mail.ru share) и кнопка «Скачать в Загрузки».

### Самообновление магазина (`tbox-store`)

Карточка `tbox-store` (`vad.dashing.store`) — обычная запись каталога.
На ГУ Store сравнивает свой `versionCode` с каталогом: при обновлении
показывает баннер «Обновить магазин» и кнопку на карточке; «Открыть» /
«Удалить» для себя скрыты.

Версии ведёт `store/build.gradle.kts` и журнал
[`store/Changelog.dm`](../../store/Changelog.dm). Перед публикацией:
поднять `versionCode`, обновить `versionName`, дописать блок в Changelog.

Публикация новой версии Store:

1. Собрать `./gradlew :store:assembleRuRelease` и
   `:store:assembleEnRelease` (или debug).
2. В менеджере выбрать `tbox-store` → **Заменить APK…** для `ru`, затем
   для `en` (flavor угадывается из имени `store-…-ru-….apk`).
3. Сохранить описание при необходимости → дождаться sync Яндекса и
   скопировать дерево на Mail.ru (включая `files\`).

У DCL Install во вкладке «Файлы в Загрузки» лежит APK лаунчера: магазин при
скачивании установщика сохраняет его в `Загрузки/<папка>/`, чтобы выбрать
в DCLInstall. Сам лаунчер обновляется отдельной карточкой.

## Раскладка на диске

```text
AppStore/
  release/apps/
    catalog.meta.json
    catalog.json          ← собирает программа
    mqtt/
      version.json
      mqtt-….apk
    dclinstall/
      files/              ← файлы карточки → Загрузки/<папка>/
        …
    …
  dev/apps/
    …
```

CLI без GUI (из корня репо):

```bat
python tools\build_apps_catalog.py --apps-dir D:\YandexDisk\AppStore\release\apps --write
```

Подробности формата: [docs/APP_STORE_PLAN_RU.md](../../docs/APP_STORE_PLAN_RU.md).
