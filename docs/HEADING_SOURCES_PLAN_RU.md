# План: источники курса (CAN, телефон, компас) и геопозиция с телефона

Курс нужен улучшенной геопозиции (`MockLocationJob`, режимы `MockCanSpeedMode`): без GNSS машина ведётся счислением по скорости CAN и курсу. Сейчас курс берётся из гироскопа ГУ, руля или их гибрида (`MockHeadingSource`: `GYRO`, `STEER`, `GYRO_STEER`). Этот план добавляет курс по CAN-колёсам, гироскоп и компас телефона и геопозицию с телефона.

Связанные документы: [WHEEL_PULSE_ODOMETER_RU.md](WHEEL_PULSE_ODOMETER_RU.md), [PHONE_COMPANION_BLE_PLAN_RU.md](PHONE_COMPANION_BLE_PLAN_RU.md) §8, [MBCAN_VHAL_PARAMETERS_RU.md](MBCAN_VHAL_PARAMETERS_RU.md), [reference/vhal_properties_a10_2026-10-21.csv](reference/vhal_properties_a10_2026-10-21.csv).

---

## 1. Почему: на A10 нет гироскопа

Проверено на ГУ A10 (192.168.1.7, 21.10.2026). Ни один из трёх путей гироскопа не даёт данных.

| Путь | Что в коде | Что на ГУ |
|------|------------|-----------|
| Navi DR Adayo | `A10NaviDrBackend`, binder `adayo.service.navi.v2.0` | Сервиса и пакета навигации Adayo нет: `binder null`. |
| Android `SensorManager` | `AndroidSensorDrBackend` (запасной) | HAL `sensors.ac8x.so` объявляет ASM330LHH (акселерометр + гироскоп), но драйвера в ядре нет: нет input-устройства «ST ASM330LHH Gyroscope Sensor», на шинах I²C датчика нет. Подписка приложения кончается `SensorService: Error activating sensor 4 (Operation not permitted)`. |
| INS от MCU через VHAL | не используется | Свойства `MPU_ASK_INS_DATA_INFO` (0x21400CC7), `MCU_SEND_INS_ANGULAR_VELOCITY` / `_ACCELERATION` / `_TEMPERATURE` / `_SPEED` (0x21400CC8…CB) есть, но нулевые, `timestamp 0`. Запрос `MPU_ASK_INS_DATA_INFO=1` к MCU по UART не уходит, ответа нет. |

Магнитометра на ГУ нет ни на A9, ни на A10.

## 2. Источники

### 2.1 CAN (A9 и A10)

| Сигнал | A9 (mbCAN) | A10 (VHAL) | Для курса |
|--------|------------|------------|-----------|
| Импульсы колёс LHF / RHF / LHR / RHR | `eMBCAN_VEHICLE_WHEEL` → `MBCanVehicleWheel` | `R_0400_ESP_5_*PulseCounter`: 289412182 / 289412179 / 289412175 / 289412177 | Поворот = (ΔsR − ΔsL) / колея, по задним колёсам |
| Поперечное ускорение | `MBCanVehicleSpeed.fLateraAccaleleration` | `R_0900_YAS_1_LateraAccaleleration` (289414960) | ω ≈ a_lat / v, только для подтверждения |
| Угол руля | уже есть (`STEER`) | уже есть (`MCU_REPLY_STEERING_WHEEL_ANGLE`, `SteeringAngleDomain`) | Модель велосипеда, `SteerHeadingIntegrator` |
| Скорости колёс `0x310` | через TBox (`CanFramesProcess`) | через TBox | Запасной дифференциал колёс, только при связи с TBox |

Готового сигнала угловой скорости рыскания (yaw rate) нет ни на A9, ни на A10.

### 2.2 Телефон (только Android)

| Данные | Откуда в телефоне | Зачем |
|--------|-------------------|-------|
| Координаты, скорость, курс по движению, точность | `LocationManager` GPS / Fused | Новый источник геопозиции |
| Угловая скорость вокруг вертикали | `TYPE_GYROSCOPE`, проекция на гравитацию (`TYPE_GRAVITY` / акселерометр) | Курс как от гироскопа, при любой ориентации телефона |
| Азимут по компасу | `TYPE_MAGNETIC_FIELD` + гравитация, без `TYPE_ROTATION_VECTOR` (внутри у него смешан гироскоп) | Абсолютный курс, в том числе на стоянке |
| Модуль поля, точность магнитометра | `onAccuracyChanged`, |B| | Отбраковка компаса |

## 3. Варианты выбора источника курса

`MockHeadingSource` расширяется. Выбор один на оба ГУ; недоступные на этом ГУ варианты видны, но помечены «недоступно» с причиной.

| Вариант | Что делает | A9 | A10 |
|---------|------------|----|-----|
| `GYRO` | Гироскоп ГУ (`YawIntegrator`) | да | нет (см. §1) |
| `STEER` | Руль | да | да |
| `GYRO_STEER` | Гироскоп + руль (как сейчас) | да | нет |
| `WHEELS` | Дифференциал импульсов задних колёс | да | да* |
| `WHEELS_STEER` | Колёса основной, руль на малой скорости и для подтверждения | да | да* |
| `PHONE_GYRO` | Гироскоп телефона | да | да |
| `PHONE_COMPASS` | Компас телефона, абсолютный курс | да | да |
| `PHONE_GYRO_COMPASS` | Гироскоп телефона для поворотов + компас для медленной поправки абсолютного курса | да | да |

\* После проверки на A10 в движении, что импульсы приходят через VHAL с достаточной частотой (§7, этап 0).

Поперечное ускорение отдельным вариантом не выбирается: только вес подтверждения поворота в гибридах.

Если выбранный источник замолчал (нет данных дольше порога, телефон отключился, компас забракован), курс временно берётся из следующего доступного по цепочке: телефон → колёса → руль. Факт подмены виден в статусе и пишется в geo-debug.

## 4. Курс по CAN-колёсам

Новый `WheelHeadingIntegrator` рядом с `SteerHeadingIntegrator`.

- Вход: те же сэмплы импульсов, что у `WheelPulseOdometer` (одна подписка, без второго опроса mbCAN/VHAL; правила потоков mbCAN из [MBCAN_JNI_THREADING_RU.md](MBCAN_JNI_THREADING_RU.md)).
- Δψ = (ΔsRR − ΔsRL) / B, где Δs = импульсы × k (k из калибровки `WheelPulseOdometer`), B — эффективная колея.
- B калибруется автоматически по GNSS-курсу (как `SteerCalibrationStore` / `GyroBiasStore`), стартовое значение — паспортная колея.
- Переполнение счётчиков и пропуски сэмплов — как в `WheelPulseOdometer`.
- Пробуксовка: если асимметрия передних и задних пар расходится сильнее порога (slip gate из `WheelPulseOdometer` §4.3), сэмпл не учитывается, курс на это время из руля.
- Малая скорость: ниже порога (≈5 км/ч, уточнить по данным) дискретность импульсов даёт шум, в `WHEELS_STEER` вес переходит к рулю.
- Задний ход: знак Δψ по передаче (`considerReverse`).
- Поперечное ускорение: при v > ≈20 км/ч ω_lat = a_lat / v сравнивается с ω колёс; сильное расхождение снижает доверие к колёсам.

## 5. Телефон

### 5.1 Фоновая работа на телефоне

Сейчас приложение `:phone` держит связь, только пока открыт экран. Нужно:

- Foreground service с постоянным уведомлением, типы `location` и `connectedDevice`; разрешения `FOREGROUND_SERVICE_LOCATION`, `FOREGROUND_SERVICE_CONNECTED_DEVICE` (Android 14+), `ACCESS_FINE_LOCATION`, `ACCESS_BACKGROUND_LOCATION`.
- Автозапуск при появлении ГУ: связь с ГУ через `CompanionDeviceManager`. Тогда система будит приложение по Bluetooth и разрешает старт foreground service из фона (Android 12+).
- Сенсоры внутри foreground service работают в фоне.
- Экран-инструкция «отключить оптимизацию батареи» (Xiaomi, Huawei, Samsung убивают службы).
- Переключатели на телефоне: «Отдавать геопозицию», «Отдавать гироскоп», «Отдавать компас». По умолчанию выключены.

### 5.2 Транспорт и сообщения

Только прямой путь RFCOMM (`PhoneDirectWire`, `PhoneDirectLink` / `PhoneDirectServer`). Путь через ESP32 по BLE не подходит: интервал 200–300 мс, эфир делится с пультами.

Новые зашифрованные пакеты в том же формате, что CMD / REFRESH (`PhoneBleCodec`), от телефона к ГУ:

| Пакет | Период | Содержимое |
|-------|--------|------------|
| `LOC` | 1 с (или частота GNSS телефона) | время фикса (UTC мс), широта, долгота, высота, скорость, курс по движению, точности позиции / скорости / курса, число спутников |
| `YAW` | 100–200 мс | монотонное время телефона (начало и конец окна), интеграл угла вокруг вертикали за окно, признак «телефон неподвижен относительно машины» |
| `MAG` | 1 с | монотонное время, азимут магнитный, модуль поля мкТл, точность Android (0–3), наклон телефона |

Телефон сам интегрирует гироскоп и шлёт приращения: десятки байт в секунду. Время: ГУ хранит смещение между монотонными часами телефона и своими по каждому пакету (минимум задержки за скользящее окно).

Склонение (магнитный → истинный курс) считает ГУ через `android.hardware.GeomagneticField` по текущей позиции.

### 5.3 Гироскоп телефона

- ω_vert = ω · ĝ (проекция на единичный вектор гравитации): ориентация телефона в держателе не важна.
- Отбраковка: вектор гравитации в системе телефона повернулся больше порога или скачет акселерометр — телефон в руке или упал; окно не учитывается, курс по цепочке подмены.
- Смещение нуля и масштаб калибруются на ГУ по GNSS-курсу так же, как для гироскопа ГУ (`GyroBiasStore`, `OnlineYawCalibEstimator`), но в отдельном хранилище.

### 5.4 Компас телефона

Пользователь проверял: компас телефона в машине правильно показывает север. Поэтому компас — полноценный отдельный источник, а не только поправка.

- Азимут в системе машины: азимут телефона + поправка установки телефона. Поправка (угол между осью телефона и осью машины) калибруется по GNSS-курсу в движении по прямой; до калибровки — по первому надёжному GNSS-курсу.
- Жёсткое железо машины: остаточное постоянное смещение азимута калибруется так же по GNSS-курсу, отдельно по секторам курса (8 секторов по 45°), чтобы учесть зависимость ошибки от направления.
- Отбраковка: точность Android < 2, |B| вне 25–65 мкТл (магнитный держатель, MagSafe, арматура), скачок |B| или азимута без поворота по колёсам и рулю, телефон в руке (§5.3).
- Сглаживание: медианный фильтр 3–5 с; в `PHONE_COMPASS` курс между сэмплами ведёт колёса / руль, компас подтягивает абсолютное значение.
- Стоянка: на неподвижной машине компас — единственный источник абсолютного курса; при старте счисления без GNSS (паркинг, тоннель) начальный курс берётся из компаса, если он не забракован.

### 5.5 Геопозиция с телефона

- Новое значение `LocationSource.PHONE` рядом с `TBOX`, `ESP32`, `ANDROID`, `USB`.
- Пакет `LOC` идёт в тот же путь, что остальные внешние источники (подача в mock-позицию и в режимы `MockCanSpeedMode`).
- Пропадание телефона = потеря фикса: работают удержание и счисление как при пропадании GNSS.

## 6. ГУ: интерфейс и диагностика

- Экран геопозиции: выбор источника курса с пометкой «недоступно: причина»; статус активного источника и подмены; для телефона — связь, возраст пакетов, точность компаса, |B|.
- `DrSensorRepository` / `AndroidSensorDrBackend`: показывать отказ HAL явно («сенсорный HAL отказал в активации»), а не пустые значения. Признак — подписка зарегистрирована, а сэмплов нет дольше 3 с.
- Geo-debug (`GeoDebugLogRecorder`, `tools/geo_debug_analyze.py`): новые поля — Δψ колёс, ω_lat, ω телефона, азимут компаса, |B|, источник курса на каждом тике, причины отбраковки.
- Калибровки (колея, гироскоп телефона, установка телефона, сектора компаса) — в экран калибровок рядом с рулём и гироскопом, со сбросом.

## 8. Риски

- Импульсы колёс на A10 через VHAL могут приходить редко (`ON_CHANGE`, батчи MCU) — проверить на этапе 0.
- Компас: магнитные держатели, рамы сидений, кабели питания рядом с телефоном; мосты, трамвайные пути, паркинги.
- Телефон: энергосбережение производителей, нагрев, разряд без зарядки, разрывы Bluetooth. Телефон — дополнительный источник, база — CAN.
- RFCOMM на A9 проверен вместе с HFP и A2DP, но поток каждые 100–200 мс на долгой поездке ещё не проверялся.
