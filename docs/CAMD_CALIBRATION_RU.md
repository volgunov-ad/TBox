# Штатная калибровка камер AVM (`original_ds`) и виды camd по ней

Разбор штатной калибровки кругового обзора (AVM) головного устройства Jetour Dashing (Android 9, mbCAN) и план её использования в `:camd`. Факты про камеры ГУ: [CAMERAS_A9_RU.md](CAMERAS_A9_RU.md). Устройство и API camd: [CAMD_RU.md](CAMD_RU.md).

Состояние: анализ завершён 18 ноября 2026, реализация в camd выпущена (0.8.0 — источники 40–45 и пресеты `stock_*`; 0.8.1 — стоковые источники в UI). Утверждённый подход: существующие виды, пресеты и коррекции camd не меняются; штатные калибровочные виды добавляются отдельными **источниками 40–45** и встроенными пресетами `stock_*`; старые и новые изображения можно показывать одновременно.

## Где лежит

`/vendor/etc/mbhal/avm/original_ds/` — 61 файл, права `644` (читаются без root). Это рабочая калибровка варианта `avmcamtype=0`. Как снять:

```
adb connect 192.168.1.128:5555
adb pull /vendor/etc/mbhal/avm/original_ds
```

Состав:

| Группа | Файлов | Формат | Кем используется |
|---|---|---|---|
| `camera_para` (1143 Б) | 1 | текст, 94 строки | разбор ниже; camd читает |
| `camarray_vert1..6` | 6 | binary, LE float32 | меши шести штатных видов; camd читает |
| `camarray_text1..6` | 6 | binary, LE float32 | UV тех же мешей; camd читает |
| `array_vert<XY>_<Z>` | 24 | binary, LE float32 | промежуточные таблицы AVMapp; camd не читает |
| `array_text<XY>_<Z>` | 24 | binary, LE float32 | то же; camd не читает |
| `calib_front.raw/.yuv`, `calib_rear.raw/.yuv` | 4 | сырье авто-калибровки | AVMapp; camd не читает |

## camera_para

94 строки, числа — текст с десятичной точкой. Структура: четыре блока по 22 строки (камеры 0–3: строки 1–22, 23–44, 45–66, 67–88) и шесть строк описания видов (строки 89–94, по порядку 1:1 к `camarray1..6` — соответствие косвенное, проверить на стенде).

Блок камеры:

| Строки блока | Поле | Значения (пример — камера 0) |
|---|---|---|
| 1–6 | шесть коэффициентов дисторсии | `-0.018759 0.446153 -0.487079 -1.09988 -0.0123818 -0.0174583` |
| 7–10 | нули | `0 0 0 0` |
| 11–13 | матрица K, 3×3 | `128 0 640` / `0 128 400` / `0 0 1` — fx=fy=128, cx=640, cy=400 (половины 1280×800) |
| 14–19 | те же шесть коэффициентов дисторсии, повтор | — |
| 20 | масштаб | `128` |
| 21 | экстринсики, пять чисел | `3800 6960 6960 -1900 3480` |
| 22 | хвост | `0 0` |

Экстринсики всех камер (единицы и точная семантика не расшифрованы; camd их не использует — меши уже содержат результат):

| Камера | Строка 21 |
|---|---|
| 0 (перед) | `3800 6960 6960 -1900 3480` |
| 1 (право) | `6960 3800 6960 1900 3480` |
| 2 (зад) | `3800 6960 6960 1900 -3480` |
| 3 (лево) | `6960 3800 6960 -1900 -3480` |

Строки 89–94 — виды. Поля с нуля: `[0]` камера калибровки, `[1]` тип (всюду `2`), `[2..4]` rotX/rotY/rotZ (рад, наклоны ±0.15), `[5..6]` px/py, `[7..8]` pw/ph — прямоугольник вида на штатном экране, `[9..10]` srcW/srcH = `1280 800`, `[11]` всегда `1`, `[12]` зеркало (см. ниже), `[13]`=`4` и `[14]`=`1` — не расшифрованы.

| № (↔ camarray) | Камера | rotX rotY rotZ | px py pw ph | Зеркало `[12]` |
|---|---|---|---|---|
| 1 | 0 (перед) | `0 -0.01 -0.02` | `250 100 820 580` | 0 |
| 2 | 1 (право) | `0 0 0` | `175 228 915 514` | 0 |
| 3 | 2 (зад) | `0 0.02 0` | `255 130 775 584` | **1** |
| 4 | 3 (лево) | `0.05 0 0` | `161 248 915 514` | 0 |
| 5 | 0 (перед) | `0.05 -0.15 0` | `148 0 934 720` | 0 |
| 6 | 2 (зад) | `0.05 -0.05 0` | `206 88 928 604` | **1** |

Виды 1–4 — «2D» каждой камеры, 5–6 — широкие перед/зад (другая камера, плотнее меш и заметный наклон rotY −0.15). Зеркало `=1` только у камеры 2 — задняя картинка в стоке зеркалится. Для camd существенен только `[12]`: повороты и дисторсия уже запечены в мешах, rot/px/py/pw/ph — информационные (раскладка штатного экрана AVM).

## camarray_vertN / camarray_textN — меши видов

Бинарные, little-endian float32, без заголовка. Оба файла одного вида — треугольные списки (GL_TRIANGLES) с равным числом треугольников:

| Вид (предположительно) | Файлы | Байт vert/text | Треугольников |
|---|---|---|---|
| 1 · 2D перед (кам 0) | `camarray_vert1` / `camarray_text1` | 85608 / 57072 | 2378 |
| 2 · 2D право (кам 1) | `camarray_vert2` / `camarray_text2` | 86112 / 57408 | 2392 |
| 3 · 2D зад (кам 2) | `camarray_vert3` / `camarray_text3` | 84240 / 56160 | 2340 |
| 4 · 2D лево (кам 3) | `camarray_vert4` / `camarray_text4` | 86112 / 57408 | 2392 |
| 5 · широкий перед (кам 0) | `camarray_vert5` / `camarray_text5` | 121824 / 81216 | 3384 |
| 6 · широкий зад (кам 2) | `camarray_vert6` / `camarray_text6` | 104904 / 69936 | 2914 |

- `camarray_vertN` — позиции вершин: 3 float на вершину, 9 float (36 байт) на треугольник. Позиции — квад [−1, 1]² (NDC шейдера), сетка ~50×50.
- `camarray_textN` — UV: 2 float на вершину, 6 float (24 байта) на треугольник. UV — точки выборки из исходного fisheye-кадра 1280×800: дисторсия объектива и проекция «запечены» в меше, шейдеру остаётся passthrough-семплинг.
- vert2/text2 и vert4/text4 совпадают по размерам — правое и левое «2D» — зеркальная пара мешей.
- Проверка целостности: `len(vertN) == 1.5 * len(textN)` (9 float против 6 float на треугольник) — у всех шести видов сходится.

Предпросмотр мешей (numpy + PIL, достаточно каталога `original_ds`):

```python
import numpy as np
from PIL import Image, ImageDraw

for n in range(1, 7):
    v = np.fromfile(f"camarray_vert{n}", dtype="<f4").reshape(-1, 3, 3)
    t = np.fromfile(f"camarray_text{n}", dtype="<f4").reshape(-1, 3, 2)
    assert len(v) == len(t)
    img = Image.new("RGB", (512, 512), "black")
    d = ImageDraw.Draw(img)
    for tri in v:
        d.polygon([((x + 1) / 2 * 512, (1 - y) / 2 * 512) for x, y, _ in tri], outline="green")
    img.save(f"vert{n}.png")
    print(n, len(v), "tris, uv", t.min(), t.max())
```

## array_vert<XY>_<Z> / array_text<XY>_<Z>

Имена `<камера 1..4><вид 1..2>_<часть 0..2>` (например `array_vert11_0`, `array_text12_1`). Тот же формат — little-endian float32 без заголовка, но хранение **не** треугольный список: отношения байтов vert/text внутри пары — ровно 2:1 у видов `<X>1` и 3:2 у `<X>2` — похоже на индексированную геометрию с разной длиной вершины. Точная семантика не расшифрована. camd эти файлы не читает.

## calib_front / calib_rear и авто-калибровка

`calib_front.raw/.yuv` и `calib_rear.raw/.yuv` — сырье авто-калибровки AVMapp. На устройстве авто-калибровка живёт в `/early_services/earlydata/avm/calibration/` (`drwx------ root`) и пишется только для передней и задней камер. Нативные исходники: `vendor/qcom/proprietary/ais/test/X50_RVCAVM`. Свойство `avmcamtype=0` выбирает вариант калибровки `original_ds` — этот набор. Root на этой ГУ недоступен (`adb root` отказ, `su: not found`), поэтому папка авто-калибровки нечитаема и неизвестно, перекрывает ли она `original_ds` у стока.

## calibration.zip ≠ устройство

`calibration.zip` (из `Downloads`) — **не** эта калибровка: все 31 файл в нём отличаются от копий с устройства. Например `camera_para` в zip — 1051 Б и содержит строку `0 3.125`, на устройстве — 1143 Б и `0 0`. Эталон — только файлы, снятые с ГУ.

## План интеграции в camd (утверждён)

Принцип: поведение существующего не меняется. Штатные виды — новые «камеры»/источники; окно стокового вида можно открыть одновременно с сырым окном той же физической камеры.

| id | Вид | Физический вход | Меш | Встроенный пресет |
|---|---|---|---|---|
| 40 | 2D перед | 8 | `camarray` 1 | `stock_front` |
| 41 | 2D право | 5 | `camarray` 2 | `stock_right` |
| 42 | 2D зад | 9 | `camarray` 3 | `stock_rear` |
| 43 | 2D лево | 4 | `camarray` 4 | `stock_left` |
| 44 | широкий перед | 8 | `camarray` 5 | `stock_wide_front` |
| 45 | широкий зад | 9 | `camarray` 6 | `stock_wide_rear` |

1. **Загрузчик** (`CamdCalibration`): парсинг `camera_para` (94 строки: 4×22 + 6) и `camarray_vert/text1..6` с устройства (`/vendor/etc/mbhal/avm/original_ds/`, права 644 — root не нужен, ничего не копируем). Валидация: число строк, парсинг float, равенство числа треугольников vert/text, правдоподобные границы позиций и UV. Кэш в памяти процесса. Файлы отсутствуют или не разобрались — `OPEN` источников 40–45 отвечает ошибкой (предварительно `stock_cal_missing`).
2. **Ключ окон — источник, а не вход.** Сейчас окна ключуются по input id и повторный `OPEN` той же камеры двигает окно. Для 40–45 ключ — id источника: у входа 8 могут одновременно жить сырое окно и `stock_front`/`stock_wide_front`. `grab.desired` по-прежнему перечисляет физические входы; логика остановки AVM (`heldByAvm`) маппит источник → физический вход.
3. **Меш-рендер.** Для 40–45 — свой путь отрисовки: GL_TRIANGLES из vert/text, шейдер passthrough UV; существующий шейдер квадра с аналитическими UV не трогается. Поворот/flip/crop пресета применяются к позициям вершин в vertex-стадии; `CamdLensCorrection` для 40–45 игнорируется (дисторсия запечена); зеркало — uniform из поля `[12]` конфига (виды 3 и 6). Ориентация V: UV мешей и текущий шейдер camd используют одно соглашение (`v=0` — первая строка кадра в памяти) — финально сверить на стенде.
4. **Пресеты и валидация источников.** Встроенные пресеты из таблицы выше: `PRESETS` сразу отдаёт их, TBox Monitor и DCL работают без правок — адресация по имени (`OPEN preset=имя`). Резолвер источников расширяется с `KnownInputs.byId` до общего (сырые входы + 40–45) в точках: `CamdCommands.kt` (разбор OPEN), `CamdPreset.kt` (сохранение/чтение пресетов), `CameraWindows.kt` (открытие окна, AVM), `CamdBackup.kt` (импорт).
5. **UI.** Изначальный план («UI v1 не меняется, сток — только через пресеты и API») пересмотрен 18 ноября 2026: вкладка «Камеры» и редактор пресетов показывают штатные виды обычными источниками — чипы и названия идут из `CamdSources.allSources()` / `camera()` («40 · сток: …»), своим пресетам можно назначить стоковый источник; в UI есть подсказки, что визуальные коррекции на сток не действуют (поворот, зеркала и вырезка пресета работают); вкладка «Регистратор» осталась на сырых входах. Той же правкой устранён перескок вкладки после первого запуска UI: опросник состояния писал устаревший снапшот поверх переключения вкладки — все writers переведены на атомарный `MutableStateFlow.update`, а STATUS/qcarcam-лог кэшируются по (длина, mtime).

## Что проверено, что нет

Проверено разбором локальной копии: форматы файлов, раскладка `camera_para`, размеры и согласованность треугольников всех мешей, зеркало только у камеры 2, zip ≠ устройство. На стенде 18.11 (без камер): калибровка загружается, `OPEN preset=stock_front/wide_front/rear` отвечают `OK`, окна рендерятся плейсхолдером «жду кадр», несколько стоковых окон живут одновременно.

Не доказано, проверить на стенде/машине:

- соответствие «строка вида ↔ `camarrayN`» (сейчас — косвенная улика: порядок строк и пары 2D/широкие);
- поведение зеркала против штатной задней картинки;
- ориентация V и совпадение с стоком вживую;
- поля `[13]`=4 и `[14]`=1 конфиг-строк, точная семантика rotX/rotY/rotZ и px/py/pw/ph (camd v1 их не использует);
- связь авто-калибровки `/early_services/earlydata/avm/calibration/` с `original_ds` (root недоступен).
