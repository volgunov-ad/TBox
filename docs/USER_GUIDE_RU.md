# Руководство пользователя TBox Monitor

Приложение **TBox Monitor** (версия **0.18.0**) для головного устройства Jetour Dashing: обмен с блоком TBox (модем, CAN, геопозиция, служебные команды), плитки на главном экране и в плавающих панелях, учёт поездок и топлива, климат/сиденья/багажник/зеркала через **mbCAN** или **VHAL**, темы `.tboxtheme`, OTA-обновления.

Документ из **трёх частей**: (1) **пошаговая работа** с интерфейсом; (2) **ARM/MCU и логика перезагрузок** внутри TBox; (3) **таблицы опций** в приложении и безопасность.

## Кратко: режимы CAN (mbCAN / VHAL)

В приложении есть два режима работы с CAN:

- **ГУ с Android 9** -> используется backend **mbCAN**.
- **ГУ с Android 10** -> используется backend **VHAL** (`android.car` / `CarPropertyManager`).

> «Android 10» здесь — название линейки Adayo/VHAL в приложении. На самом ГУ в заводском меню версия может отображаться как Android 10 (`Build.VERSION.RELEASE`), при этом API платформы часто остаётся 28 — подробнее в [CAN_BACKENDS_RU.md](CAN_BACKENDS_RU.md).

Переключение находится в настройках (две кнопки выбора типа ГУ).

### Что делает приложение при переключении

1. Сохраняет выбранный режим в настройках (`DataStore`).
2. Общий слой `UniversalCanRepository` переключает активный backend.
3. Старый backend отключается (`unbind`), новый подключается (`bind`).
4. Все виджеты и экран настроек продолжают работать через единый API.

Это сделано специально, чтобы поведение Android 9 не ломалось при доработках Android 10.

### Как понять, что Android 10 (VHAL) работает

В журнале (экспертный режим) должны быть строки:

- `VHAL connected, propertyService=property`
- `Availability: AVAILABLE`
- при действии в UI: `SetProperty ... result=true`

Если есть `result=true`, команда реально записана в VHAL.

### Подписка и интервалы обновления (кратко)

- **Android 9 / mbCAN**: используется и push-callback, и poll.
  - обычный poll: примерно раз в **30 сек**;
  - после команды: burst-poll примерно раз в **1.5 сек** (около **15 сек**).
- **Android 10 / VHAL**: используется push-callback + poll fallback.
  - push: `CarPropertyManager.registerListener(..., 0.0f)` для активных `propertyId`;
  - poll fallback: как в mbCAN — обычно примерно раз в **30 сек**;
  - после успешных команд: burst-период примерно раз в **1.5 сек** (около **15 сек**).

### Типовые проблемы и что это значит

- `VHAL connect failed ...`  
  Проблема на этапе подключения к `Car`/`CarPropertyManager`.

- `POSSIBLE_PERMISSION ... SecurityException ... requires android.car.permission...`  
  Ограничение прав на конкретный `propertyId` (часто на уровне системы/подписи ГУ).

- `SetProperty ... result=false` без `SecurityException`  
  Обычно проблема маппинга `propertyId` или значения команды.

### Быстрый чеклист после установки

1. Установить APK.
2. В настройках выбрать **ГУ с Android 10**.
3. Включить экспертный режим.
4. Открыть журнал.
5. Проверить 2-3 виджета/настройки (например, drive mode).
6. Убедиться, что в логе есть `Availability: AVAILABLE` и `SetProperty ... result=true`.

Подробная техническая версия (архитектура, маппинг, backend lifecycle):  
`docs/CAN_BACKENDS_RU.md`

## Часть 1. Пошаговые инструкции

### 1.1. Первый запуск и проверка связи

1. Установите приложение и откройте его на ГУ.
2. Примите запрошенные разрешения, если планируете использовать соответствующие функции (хранилище для файлов, геолокация, уведомления для виджета музыки и т.д.).
3. Если нужны виджеты **«Тема день/ночь»** или **«Регулировка зеркал»** — сразу выдайте права на системные настройки (см. §1.4b ниже).
4. В левом меню откройте **«Настройки»**, найдите блок **«Получение данных от TBox»** и включите **«Получать данные CAN»**. Для геопозиции выберите **источник** на вкладке **«Геопозиция»**: **TBox**, **Компаньон**, **USB** (прямой GNSS) или **Android** (системный GPS ГУ).
5. Вернитесь в меню, откройте **«Модем»** и дождитесь появления строк с данными.
6. Разверните подписи в боковом меню (иконка вверху полоски меню) и посмотрите внизу: строка о **подключении TBox** должна быть зелёной, когда связь с блоком есть.

### 1.2. Как ходить по разделам

1. Слева — **меню**. Нажмите иконку **открыть/закрыть** вверху полоски, чтобы показать или скрыть **названия** пунктов.
2. Нажмите **«Главная»** — откроется **главный экран** (обои и панели с плитками), меню спрячется.
3. Чтобы снова открыть список разделов, на главном экране нажмите **плавающую кнопку с иконкой разделов** (её можно перетаскивать по экрану).
4. Любой другой пункт меню открывает **вкладку** справа (Модем, Плитки, Настройки и т.д.).

**Порядок пунктов** после «Главная»: Модем → AT-команды → Геопозиция → Данные авто → Поездки → **Заправки** → **Темы** → Настройки → Настройки главного экрана → **Настройки автомобиля** → Журнал → Информация → CAN → Плитки (фактический порядок зависит от настраиваемого левого меню; «Настройки» и «Настройки главного экрана» всегда доступны).

Пункты **AT-команды**, **Журнал** и **CAN** появляются только после включения **«Экспертный режим»** в «Настройках». Без экспертного режима этих строк в меню нет.

### 1.3. Настроить главный экран с нуля

1. Меню → **«Настройки главного экрана»**.
2. (По желанию) Включите **«Автоматически открывать главный экран при запуске»** и при необходимости задайте **задержку автозапуска** (0–60 с, по умолчанию 2 с) — открытие главной страницы после загрузки ГУ (в т.ч. если служба уже работала до `BOOT_COMPLETED`; при неудаче — повторные попытки).
3. **Обои:** подпись про светлую тему → **«Выбрать изображение»** → укажите файл; для удаления обоев — **«Удалить»** (когда картинка задана). То же для **тёмной** темы.
4. Включите или выключите переключатель **масштаба фона (Crop)** — картинка на весь экран с обрезкой или вписывание целиком (см. подпись на экране).
5. В блоке **«Панели главного экрана»** нажмите **«Добавить»**.
6. В **выпадающем списке** выберите созданную панель. В поле **имени** введите удобное название и нажмите кнопку **переименования** (она активна, когда имя изменилось).
7. Включите **«Показывать панель на главном экране»**.
8. При необходимости задайте **число строк** и **столбцов** плиток, **открытие программы одиночным нажатием** и **индикатор отключения TBox**.
9. Поля **ширина, высота, позиция X и Y в %** задайте так, чтобы панель занимала нужную область (можно начать с значений по умолчанию и потом подправить).
10. Меню → **«Главная»** — убедитесь, что панель видна.
11. **Переместить или изменить размер панели на экране:** удерживайте панель и перетаскивайте; размер меняйте, как показывает интерфейс при удержании/за край (следуйте подсказкам на экране).
12. **Назначить плитку:** на главном экране **долго нажмите** ячейку → в диалоге выберите, что показывать → при необходимости откройте **«Дополнительно»** (цвета по светлой/тёмной теме, масштаб, скругление; для музыки — плееры) или **«Вся панель»** (имя, строки/столбцы, **фон и скругление всей панели**, **открытие программы одиночным нажатием**, индикатор TBox) → сохраните. Повторите для остальных ячеек.
13. **Одиночное нажатие на плитку на главном экране:** при включённой опции **«открывать окно программы…»** по тапу открывается только вкладка **«Поездки»**, если на плитке выбран виджет **активной поездки** (или упрощённый вариант); для остальных плиток эта опция сейчас **ничего не делает**.

**Вторая и следующие панели:** снова **«Добавить»** в блоке панелей; в списке переключайтесь между панелями и настраивайте каждую отдельно. Лишнюю панель удалите кнопкой **«Удалить»** (выбранная в списке).

### 1.4. Настроить вкладку «Плитки»

1. **«Настройки»** → блок **«Настройки экрана Плитки»**.
2. Выберите **количество строк** и **столбцов** — столько будет ячеек на вкладке «Плитки».
3. При желании включите **«Показывать графики…»** на плитках.
4. Меню → **«Плитки»**.
5. **Долгое нажатие** на ячейку → выбор данных → **«Дополнительно»** при необходимости → сохранение.
6. **Короткое нажатие** по плитке выполняет действие этого виджета (запуск приложения, команды на плитке и т.д.).

Для **музыки** система может запросить доступ к **уведомлениям**. Для плитки **стороннего виджета** следуйте кнопкам выбора виджета в диалоге.

### 1.4a. Виджет «HTTP-запрос»

Виджет **«HTTP-запрос»** выглядит как «Ярлык приложения»: пользовательская иконка и подпись снизу, если включено **«Показывать название»**. Иконка выбирается отдельно для каждой плитки и привязана к конкретной панели и номеру ячейки.

В **«Дополнительно»** задайте YAML запроса. Значение по умолчанию:

```yaml
url: "http://"
```

Поддерживаемые поля:

```yaml
url: 'http://example.local/api'   # обязательно
method: POST                      # get, patch, post, put, delete; по умолчанию get
headers:
  authorization: 'Bearer token'
  content-type: 'application/json'
payload: '{"entity_id":"timer.test"}'
authentication: basic             # basic или digest; по умолчанию basic
username: user
password: pass
timeout: 10                       # секунды, по умолчанию 10
content_type: 'application/json'
verify_ssl: true
insecure_cipher: false
skip_url_encoding: false
```

Поведение по нажатию:

- если **«Открыть браузер»** включено, приложение берёт `url` из YAML и открывает стандартный браузер; HTTP-запрос внутри TBox Monitor не выполняется, зелёной/красной анимации нет, повторное нажатие блокируется на 500 мс;
- если **«Открыть браузер»** выключено, TBox Monitor выполняет HTTP/HTTPS-запрос; успешный ответ `2xx/3xx` подсвечивает плитку зелёным на 1 с, ошибка/timeout/non-`2xx/3xx` показывает Toast и подсвечивает плитку красным на 2 с;
- пока запрос выполняется, повторные нажатия игнорируются; после результата или timeout плитка остаётся заблокированной ещё 500 мс.

> Важно: YAML может содержать токены, пароли и заголовки авторизации. Эти данные сохраняются в настройках и попадают в `.tboxtheme`, если экспортировать панель с таким виджетом.

### 1.4b. Виджеты «Тема день/ночь» и «Регулировка зеркал» — права

Эти виджеты меняют **штатные** ключи головного устройства (`Settings.Global` / `Settings.System`), а не CAN. Без двух шагов ниже переключение с плитки не сработает.

1. В настройках Android откройте список приложений → **TBox Monitor** → специальный доступ / разрешения и **включите** доступ к **изменению системных настроек**.
2. Подключите ГУ по ADB и выполните:

```
adb shell pm grant vad.dashing.tbox android.permission.WRITE_SECURE_SETTINGS
```

**«Тема день/ночь»:** одиночный тап — ручная смена день ↔ ночь; двойной — авто по освещённости.  
**«Регулировка зеркал»:** одиночный тап — вкл/выкл штатного режима регулировки зеркал с подрулевого блока.  
Отдельно есть виджет **«Складывание зеркал»** (через mbCAN/VHAL) — для него эти права **не** нужны.
Одиночный тап чередует сложить/разложить по последней отправленной команде в текущей сессии приложения (состояние зеркал с шины не читается; после перезапуска снова считается, что зеркала разложены); двойной тап всегда складывает.

### 1.5. Включить плавающую панель поверх других приложений

1. **«Настройки»** → **«Настройки плавающих панелей»**.
2. Нажмите **«Добавить»** — в списке появится новая панель.
3. В **выпадающем списке** выберите панель, задайте **имя** и нажмите кнопку **переименования**, если меняли название.
4. Включите **«Показывать плавающую панель»**. Если появится запрос Android, откройте **настройки** по кнопке в диалоге и разрешите **«Отображение поверх других окон»** для TBox Monitor.
5. Установите **строки** и **столбцы** сетки.
6. Введите **ширину и высоту окна в пикселях** и координаты **X, Y** (в полях ввода минимум 50 для ширины и высоты). При необходимости уменьшите или увеличьте числа, если окно неудобно расположено.
7. Выйдите на рабочий стол или другое приложение: должно появиться **окно** с плитками.
8. **Режим редактирования:** **долгое нажатие** по окну панели включает или выключает режим редактирования (перемещение и размер).
9. **Назначить плитку:** в режиме редактирования **коротко нажмите** ячейку — диалог выбора данных откроется в **главном окне** приложения; при необходимости откройте **«Вся панель»** (строки/столбцы, фон и скругление панели, индикатор TBox, **открытие программы одиночным нажатием**).
10. **Порядок наложения:** в настройках плавающих панелей кнопка **«Порядок панелей»** — перетаскивание строк задаёт, какая панель выше других.
11. **Скрытие по приложениям:** при необходимости включите показ/скрытие панелей для выбранных foreground-приложений (может потребоваться разрешение статистики использования — следуйте подсказкам).

**Несколько плавающих панелей:** добавьте ещё одну кнопкой **«Добавить»**. На экране одновременно показываются **все панели, у которых в конфигурации включён показ** (каждая со своим положением и размером). Чтобы настроить **размер в пикселях и сетку** для конкретной панели, сначала **выберите её в выпадающем списке** в этом блоке настроек — изменения применяются к выбранной панели.

### 1.6. Включить цветные индикаторы на плитках

1. **«Настройки»** → **«Настройки виджетов для Overlays»**.
2. Включите **индикатор подключения TBox**: **красный** — нет данных от службы, **жёлтый** — нет связи с TBox, **зелёный** — связь есть.
3. Включите **индикатор геопозиции** (нужно включённое получение геоданных): **красный** — нет фикса, **жёлтый** — расхождение скорости со спутниками, **зелёный** — норма.

### 1.7. Вкладка «Модем» — пошагово

1. Меню → **«Модем»** — список обновится (служба запрашивает состояние).
2. Прочитайте блок **«Данные модема и SIM»** (IMEI, ICCID, IMSI, оператор) — так проверяете, видит ли TBox карту и сеть.
3. В блоке **«Данные подключения»** смотрите **CSQ**, **регистрацию**, **SIM**, **сеть**, строку **APN**, **время подключения**.
4. Пролистайте **APN 1** и **APN 2** — IP, шлюз, DNS, время изменения.
5. Внизу нажмите **«Включен»**, **«Режим полёта»** или **«Выключен»** по необходимости. После нажатия кнопки кратко блокируются от повторного нажатия.

### 1.8. Вкладка «Геопозиция» — пошагово

1. Меню → **«Геопозиция»** → выберите **источник геопозиции** (TBox / Компаньон / Android / USB).
2. **Компаньон** можно выбрать только если ESP32 уже на USB и на вкладке «Компаньон» включено **«Подключаться к компаньону»** (выбор источника сам сессию не включает).
3. При источнике **USB**: в списке выберите **USB GNSS устройство** (CDC или UART-мост: CH340/CP210x/FTDI/Prolific; также u-blox/MediaTek/ST) и при необходимости **скорость** (обычно 115200; у UM980 через CP210x часто **57600** — как настроено на модуле). Кнопка **«Определить скорость»** перебирает baud (~2.5 с на вариант) и сохраняет первый с валидной NMEA (checksum). Для CP210x/CH340/FTDI/Prolific приложение делает vendor-init baud/DTR (не только CDC; у FTDI снимаются status-байты в RX). Нужно выбрать конкретное устройство — без выбора источник USB недоступен. Приложение читает NMEA (GGA/RMC/GSA/GST, при наличии VTG/ZDA) напрямую; опциональные переключатели «Запрашивать VTG/ZDA/GST» по умолчанию **выкл.** (команды Unicore отправляются только если вы их включите; GST даёт более точный `Location.accuracy` в mock). **Не выбирайте TBox и другие сетевые USB** — неверный выбор может нарушить USB Host ГУ. После permission id сохраняется с serial; при двух одинаковых адаптерах без serial открытие не начнётся наугад. Если сессия «подключена», но NMEA нет ~10 с — сессия переоткрывается.
4. Смотрите **«Последнее обновление»** и **«Последнее изменение»**.
5. Строки **«Фиксация»** и **«Правдивость»** (да/нет) — пригодность координат.
6. Ниже — координаты, спутники, скорость, курсы, UTC, **«Сырые данные»**; внизу — **RESUME LOC** / **SUSPEND LOC**.

Если пусто — проверьте связь с TBox / компаньоном / USB GNSS и выбранный источник (шаг 1–3).

### 1.8a. Вкладка «Компаньон» (USB + UM980)

1. Меню → **«Компаньон»** (пункт можно включить в настройках левого меню).

4. Блок UM980: сбросы, **«Получить конфигурацию из модуля»**, период координат (GGA+RMC), настройки, **«Загрузить рекомендуемый профиль»**, **«Сохранить конфигурацию в модуле»** (обязательно после изменений).

### 1.9. Вкладка «Данные авто» — пошагово

1. В **«Настройках»** включите **«Получать данные CAN»**.
2. Меню → **«Данные авто»** — прокрутите список.

### 1.10. Вкладка «Поездки» — пошагово

1. Меню → **«Поездки»**.
2. Поездки создаются **автоматически** по оборотам двигателя (CAN). Кнопка **«Завершить»** закрывает текущую поездку и сразу начинает новую; на полном виджете активной поездки то же действие — **двойной тап**.
3. Просматривайте список (хранится до **31** записи), отмечайте **избранное** (до **25** записей).
4. **«Настройки»** → **«Прочее»** → **минут разделения поездок** (по умолчанию **5** минут): пауза короче — та же поездка с учётом парковки; дольше — следующий запуск двигателя даст новую поездку.
5. На вкладке можно настроить **состав полей** для упрощённого и настраиваемого виджетов поездки (порядок строк).
6. **Расход и авто-заправки** — только при **активной** поездке; пороги заправки/шума — **4%** и **0,3%** бака (см. [fuel-refuels-calibration.md](fuel-refuels-calibration.md)).
7. Экспорт списка поездок в текстовый файл — кнопки на этой вкладке.

Подробная логика split, parking и перезапуска службы — [Trips.md](Trips.md).

### 1.10a. Вкладка «Заправки»

1. Меню → **«Заправки»** — таблица последних заправок (до **30** записей).
2. Правьте **литры по чеку**, тип топлива, температуру, название АЗС; при наличии сети подтягиваются **цены** по координатам.
3. Задайте **объём бака**, **число зон калибровки**, порог зрелости зоны; кнопка **обучения** по записи строит кривую датчика (каждая заправка — один раз).
4. Сброс калибровки или смена бака/зон с подтверждением обнуляет модель и флаги обучения.

### 1.10b. Настройки автомобиля (mbCAN / VHAL)

1. Меню → **«Настройки автомобиля»** (нужны CAN и поддержка функций на вашем авто; тип ГУ — Android 9 / Android 10 — в настройках).
2. Сейчас в основном: **многоуровневое** увеличение громкости со скоростью и связанные опции; раздел дополняется.
3. На плитках доступны, среди прочего:
   - климат **HVAC** (вентилятор, температура водителя/пассажира, обдув, SYNC, A/C, AUTO);
   - **багажник**, **складывание зеркал**, **режим регулировки зеркал**, **тема день/ночь** (для двух последних — права из §1.4b);
   - обогрев/вентиляция сидений и стёкол, режимы вождения (включая варианты для **6DCT**), рециркуляция, парковочный радар, режим обслуживания дворников и др.
4. Выбор типа плитки — в диалоге назначения на главном экране, вкладке «Плитки» или плавающей панели (под пунктом показываются описание и доступные жесты).

### 1.10c. Темы оформления

1. Меню → **«Темы»** (вкладка в левом меню, по умолчанию включена).
2. **Создать тему** — выберите разделы (главный экран, плавающие панели, иконки приложений/HTTP-запросов) и сохраните файл `.tboxtheme`.
3. **Применить тему** — выберите файл; настройки и ресурсы (обои, иконки, фоны плиток) подтянутся из архива.
4. **Темы по режиму вождения** — для ECO / SPORT и др. можно назначить отдельный файл; при смене режима на машине тема переключится автоматически **через 2 с после стабилизации режима** (при быстром переключении кнопкой — только финальный выбор).
5. **Очистить папку тем** — удаляет кэш неактивных тем и сбрасывает назначения по режимам (текущий вид интерфейса не откатывается).
6. **Очистить общую папку иконок** — удаляет только ручные иконки из `launcher_app_icons/`; иконки внутри тем не трогает.
7. **Очистить общую папку иконок HTTP-запросов** — удаляет только ручные иконки из `http_request_icons/`; иконки внутри тем не трогает.
8. **Очистить общую папку фонов плиток** — удаляет только ручные фоны из `tile_backgrounds/`; фоны внутри тем не трогает.
9. В диалоге плитки **«Удалить иконку из темы»** / **«Удалить картинку из темы»** (или без «из темы», если файл только в общей папке) — сначала убирают файл из активной темы, затем из общей папки.

Подробности формата, кэша на диске, подмены пути иконок и связи с резервной копией JSON — в [Themes.md](Themes.md).

### 1.14. Ручная перезагрузка TBox и головного устройства

1. **«Настройки»**, прокрутите вниз.
2. **«Перезагрузка TBox»** — только при связи с TBox; не нажимайте повторно, пока кнопка снова не активна. Это перезагрузка **ARM** (см. часть 2).
3. Рядом может быть **«Перезагрузка ГУ»** — перезапуск головного устройства (используйте осознанно).

### 1.15. Резервная копия

1. **«Настройки»** → **«Резервная копия»**.
2. **Экспорт:** **«Экспорт JSON»** → подтвердите сохранение (например, в **Загрузки**). Обои в файл **не входят**.

3. **Журнал:** откройте пункт → введите **фильтр** (не меньше 3 символов), если нужно → **«Сохранить в файл»** / сохранение в Загрузки через диалог.
4. **AT-команды:** введите команду → отправьте; результат смотрите в журнале и в поведении модема.
5. **CAN:** просмотрите список ID → при необходимости сохраните в файл. В **«Настройках»** в экспертном режиме задайте **число сохраняемых CAN-фреймов**.

### 1.17. Подмена геолокации

В **«Геопозиция»** доступен переключатель **«Подменять системные данные о геопозиции»** и рядом — **период подмены** (без экспертного режима). Координаты активного источника (**TBox**, **Компаньон** или **USB**) периодически подставляются в системный test GPS provider. При источнике **Android** подмена отключена (иначе возникает петля); выбор **Компаньон** / **USB** сам по себе подмену не включает.

При включённой подмене доступен **четырёхкнопочный** выбор режима: **прямая** (GNSS как есть), **улучшать всегда** (при живом GNSS — скорость с CAN; при потере фикса — удержание до 10 мин, дорисовка и курс по гиро), **только при пропадании геопозиции** (пока есть фиксация — GNSS без изменений; без фикса — retention/DR/CAN до 10 мин) и **постоянный расчёт** (непрерывный DR по скорости CAN и yaw с подхватом доверенного GNSS каждые **5 с**; скорость и курс в mock всегда расчётные; удержание **без лимита 10 мин**; при большом расхождении DR↔GNSS три раза подряд — флаг необходимости калибровки и фоновая калибровка в движении / ноль yaw на стоянке; дата последней калибровки на вкладке; виджет навигации **всегда синий**). Правдивость (junk-фильтр) в фоне не меняется. Индикатор в остальных режимах: зелёный — живая точка, синий — retention/DR, жёлтый — потеря без retention, красный — нет фикса.

Опционально: **«Определять мусорные фиксы»** (по умолчанию **вкл.**, доступен всегда) — влияет на **правдивость** независимо от подмены. Мусорные точки (нереальная высота/скорость, точность &gt;100 м; расхождение GPS↔CAN &gt;10% — в мусор после **5 с**, обратно после **2 с**) при включённой подмене **не пускаются в mock** (держится последняя хорошая; в режимах улучшения — retention/DR).

Последние принятые координаты и курс сохраняются на диск (не чаще раза в **60 с**; при остановке — сразу). Если при запуске ещё нет фикса и включён режим улучшения или постоянного расчёта, подмена стартует с этой точки и ведёт DR по CAN, пока не появится живой фикс (сохранённая точка не старше **24 ч**).

Внизу вкладки **«Геопозиция»** — датчики движения (источник, состояние, скорости поворота/наклона/крена, температура гироскопа, ускорение). Две кнопки статической калибровки: **наклон и ускорение** (pitch/roll гиро + ноль accel в этом положении) и **ноль** (yaw), по 3 с, с отбраковкой при большом разбросе; смещения сохраняются в настройках. Отдельно — **калибровка в движении**: набор по **сырому GNSS + CAN + гиро** (без mock/retention), окна ~1.5 с и оценка лага τ, `k_speed` (CAN→GNSS) и масштаб/знак yaw по длинным дугам (≥25°); пауза при плохом фиксе, отсутствии CAN/гиро или скачках курса; живой черновик (лаг, k_*, счётчики); прогресс; **«Достаточно»** / авто → превью (каналы без оценки сохраняют прежние значения; Save только если есть хотя бы одна оценка) → **«Сохранить»**; отдельный сброс. В блоке ниже — все сохранённые значения (bias + drive + лаг). Пробуются штатные пути ГУ (A9 LocalSocket `uds-sensor`, A10 binder Adayo NaviDR) и запасной `SensorManager`. При удержании точки без фикса (retention) курс в подмене крутится по yaw после bias, deadband и drive-масштаба, только при движении (задняя передача пока не учитывается).

Плитка навигации (стрелка) показывает курс и скорость из **mock**, если подмена включена; если выключена — из источника, с отбросом мусора при включённом «Определять мусорные фиксы». Отдельный виджет **«Данные о геопозиции»** — фиксация, правдивость (живая точка), retention, курс и скорость с источником, спутники `видимые/используемые`. При источнике **Android** счётчики спутников берутся из системного GnssStatus.

Нужны: разрешение геолокации; **Настройки разработчика** → **«Выбор приложения для фиктивных местоположений»** → **TBox Monitor**. На вкладке есть статус выбора и ссылка в настройки разработчика. Если приложения нет в списке — переустановите APK (в манифесте должно быть `ACCESS_MOCK_LOCATION`). Источник геопозиции выбирается на вкладке **«Геопозиция»** (и в настройках).

### 1.20. Прочие полезные опции (кратко)

- **Щелчок** при нажатиях по элементам UI — «Прочее» в настройках.
- **Давление в шинах:** запоминание при остановке двигателя и задержка перед обнулением при провале CAN — «Прочее».

- **OTA:** вкладка обновления — ветка «Релиз» / «Разработка», отмена загрузки, скорость и оставшееся время.
- **Права для «Тема день/ночь» и «Регулировка зеркал»** — §1.4b.
- **mbCAN/VHAL-диагностика** в журнале (подробный DEBUG) — только на текущий сеанс, в экспертном режиме; ошибки, предупреждения и редкие INFO по CAN пишутся в журнал и без этой опции.

## Часть 2. Устройство TBox: ARM и MCU

На одной плате TBox условно два узла:

- **ARM** — встроен в модем 4G с GPS (модули Neoway N720 или N725 в зависимости от версии аппаратной части TBox). На нём работает ОС Linux; к нему ГУ подключается по USB. Все перечисленные ниже программы (APP, SWD, MDC, CRT и др.) выполняются на ARM. Перезагрузка ARM **не влияет** на остальные блоки автомобиля.

- **MCU** — связан с **тремя** шинами CAN, собирает данные и передаёт их в ARM по внутренней шине (SPI), принимает команды от ARM и выдаёт их в CAN. За обмен ARM ↔ MCU отвечает программа **CRT**.

Кнопка **«Перезагрузка TBox»** в меню **Настройки** отправляет в CRT команду на перезагрузку **только ARM** — это штатный и безопасный сценарий. Перезагрузка MCU в отдельную функцию приложения не выносилась и в общем доступе не предлагалась; при экспериментах с перезагрузкой MCU на приборной панели могла появляться ошибка, которая затем пропадала.

## Программы внутри TBox (кратко)

Версии прошивки отличаются; поведение отдельных процессов может немного меняться.

### SWD (сторож)

Следит за общим состоянием OpenLinux, за другими программами (APP, MDC, LOC и т.д.) и за сетью. Если какая-то программа «падает», SWD пытается её снова запустить; при повторных сбоях инициирует перезагрузку TBox.

- На **HW 0.0.5** при сценарии с полной остановкой APP (команда **STOP** в приложении — см. ниже) типично происходит **одна** перезагрузка, после чего SWD перестаёт циклически поднимать процесс и гонять перезагрузки.
- На **остальных** рассматриваемых версиях этот цикл может **зацикливаться** и приводить к постоянным перезагрузкам.

Дополнительно перезагрузки могут инициироваться из-за проблем в мобильной сети и из-за аномалий системного таймера Linux.

Команда **SUSPEND** для SWD (в настройках: **автоматическая отправка команды SUSPEND приложению SWD**) приостанавливает эти механизмы; TBox обычно **не должен** из-за SWD перезагружаться. При этом отключается встроенная заводская защита от зависаний — используйте осознанно.

В приложении также есть опция **PREVENT RESTART** для SWD — она отключает часть проверок (сеть, аномалии), которые тоже могут приводить к лишним перезагрузкам.

### APP

Связана с облачным MQTT и передачей данных с камер; при невозможности установить соединение (в т.ч. при установленной SIM) может инициировать перезагрузку TBox **примерно раз в 30 минут**.

- На **0.0.4** и **0.0.5** для снятия этих перезагрузок обычно достаточно **SUSPEND** для APP.
- На **0.0.1** перезагрузки могут продолжаться; там нужна команда **STOP** для APP, но **только вместе с SUSPEND для SWD** — иначе возможны частые перезагрузки из-за поведения SWD.

### MDC

Получает от модема данные о сотовой сети и интернете. Внутри есть логика, которая тоже может приводить к перезагрузке (детали могут отличаться по версии). **SUSPEND** для MDC обычно убирает такие перезагрузки, но не всем это нужно — при необходимости пробуйте по месту. В настройках приложения указано, что при установленной SIM карте опции **SUSPEND/STOP для MDC** не рекомендуется включать без веской причины.

### CRT, HUM, LOC, GATE и др.

Отвечают за отдельные функции. **CRT**, в частности, принимает от SWD, APP, MDC и др. запросы на перезагрузку и выполняет перезагрузку системы TBox (на практике — сценарий с перезагрузкой ARM при использовании кнопки в приложении). **CRT отключать нельзя**: он также участвует в получении CAN-данных и других задачах.

## Часть 3. Опции предотвращения перезагрузки и таблицы

## Настройки предотвращения перезагрузки в TBox Monitor

Команды **SUSPEND** и **STOP** действуют до следующей перезагрузки TBox: после перезагрузки процессы снова стартуют в обычном режиме. **TBox Monitor** при включённых опциях может повторно отправлять команды. Всё **обратимо**: выключите опции и перезагрузите TBox вручную — поведение вернётся к заводскому.

При **смене набора** опций SUSPEND/STOP приложение предупреждает, что может потребоваться **ручная перезагрузка TBox** — следуйте подсказке на экране.

Имена опций в интерфейсе (раздел настроек про предотвращение перезагрузки):

| В приложении | Смысл |
|--------------|--------|
| Автоматическая отправка команды **SUSPEND** приложению **APP** | Приостановка APP |
| Автоматическая отправка команды **STOP** приложению **APP** | Полная остановка APP |
| Автоматическая отправка команды **SUSPEND** приложению **SWD** | Приостановка сторожа SWD |
| Автоматическая отправка команды **SUSPEND** приложению **MDC** | Приостановка MDC |
| Автоматическая отправка команды **STOP** приложению **MDC** | Остановка MDC |
| Автоматическая отправка команды **PREVENT RESTART** приложению **SWD** | Отключение части проверок SWD (сеть и др.) |

Рекомендация: для выбранного сценария включайте **только** нужные строки из таблицы ниже и **отключайте остальные** опции этого блока (включая PREVENT RESTART и MDC), если для вашей версии они не указаны.

## Что включить в зависимости от версии HW TBox и SIM

Узнать версию можно в диагностике TBox (запрос информации из TBox), в т.ч. поле версии HW.

| Версия HW TBox | SIM | Рекомендуемые опции в приложении | Примечание |
|----------------|-----|----------------------------------|------------|
| **0.0.5** | Нет | **SUSPEND** для APP | Остальные опции предотвращения перезагрузки — выкл. |
| **0.0.5** | Есть | **STOP** для APP | Остальные — выкл. Ожидайте **однократную** перезагрузку TBox — это нормальное проявление логики SWD на этой версии. |
| **0.0.4** | Нет или есть | **SUSPEND** для APP | Остальные — выкл. |
| **0.0.1** | (любая) | **STOP** для APP **и** **SUSPEND** для SWD | Остальные — выкл. Если перезагрузки всё ещё бывают, можно **дополнительно** попробовать **SUSPEND** для MDC. |

Если для вашей комбинации HW/SIM поведение отличается, ориентируйтесь на логи приложения и при необходимости сузьте набор включённых опций.

## Прочие настройки, влияющие на перезагрузки

В том же разделе настроек есть **автоматическая перезагрузка TBox** и **автоматический перезапуск модема** — это **сценарии самого TBox Monitor** при потере сети, а не заводская логика SWD/APP. При отладке «лишних» перезагрузок имейте в виду, что эти тумблеры могут добавлять свои перезапуски.

## Краткий чеклист безопасности

1. Не включайте **STOP APP** без **SUSPEND SWD** на **0.0.1** и **0.0.4** — риск непрерывных перезагрузок.
2. Не отключайте CRT — это не предусмотрено приложением и нарушит работу CAN и перезагрузок по команде.
3. Для возврата к заводскому поведению выключите опции предотвращения перезагрузки и при необходимости выполните перезагрузку TBox вручную.
