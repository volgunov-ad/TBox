# Камеры ГУ (`:camd`)

Отдельное приложение `vad.dashing.camd`. Ему отдают команды TBox Monitor и нештатный лаунчер DCL. Само оно не встроено ни в одно из них.

Факты про головное устройство, на которых это стоит: [CAMERAS_A9_RU.md](CAMERAS_A9_RU.md). Сокет `ais_server` пускает только root. Один вход камеры держит один клиент. Штатный AVM уже держит входы 4, 5, 8 и 9. Превью `:camview` (`*_sharecamera`) — другой, уже уменьшенный кадр, его для окон и записи не используем.

## Зачем

1. Открывать окно с любой камерой в любом месте экрана.
2. Писать сжатое видео в выбранную папку, если запись включена. Папка, частота кадров, предел одного файла и предел всех файлов записи настраиваются. Запись начинается вместе с системой и заканчивается вместе с ней. Файл после остановки должен открываться.

## Как устроено

Два слоя.

**Обычный процесс** хранит настройки, рисует экран и слушает `127.0.0.1:8770`. К `ais_server` он не подключается. Порт `8765` занят TBox Monitor, `8766` — локальным статусом TBox MQTT. Ошибка прослушивания не должна закрывать экран.

**Root-демон** — shell-скрипт, который `mb_daemon` поднимает один раз ([HEAD_UNITS_DEVICE_NOTES_RU.md](HEAD_UNITS_DEVICE_NOTES_RU.md) §10). Скрипт взвода заканчивается сразу, демон остаётся. Пока он жив, раз в секунду обновляет `/data/local/tmp/camd.pid` и читает команду из каталога приложения. Команда «открыть» — это XML окна и запуск `/system/bin/qcarcam_test`. «Закрыть» — завершение этого процесса.

`qcarcam_test` читает положение окна один раз при старте. Сдвиг — новый запуск, картинка на короткое время пропадает. Имеет смысл отдельно проверить, двигает ли `test_util_set_window_param` уже открытое окно. Если да, перезапуск для сдвига не нужен.

Запись, когда до неё дойдёт, делает тот же демон. Контейнер — фрагментированный MP4 (H.264): обычный MP4 пишет оглавление в конце, и обрыв питания оставляет ролик, который не открывается. Кусок в 1–2 секунды уже целый, при жёстком выключении пропадает только незакрытый хвост. На `SIGTERM` демон дописывает текущий кусок и закрывает файл. Жёсткое снятие питания без сигнала хвост всё равно обрежет — это проверяется выключением зажигания.

Пока запись выключена, демон ради неё камеру не открывает. Окна по команде от записи не зависят.

Чужие файлы в папке не удаляются. Ротация смотрит только на свои имена: новый файл по достижении предела одного файла, затем самые старые свои, пока сумма не уложится в общий предел. Частота записи — выбрасывание лишних кадров. Сенсор здесь около 25 к/с, выше него запись не пойдёт.

## План

1. Демон и одно окно: список камер, открыть в заданной точке, закрыть, открыть в другой точке.
2. Запись одного входа: фрагментированный MP4, оба предела размера, частота кадров, включение, старт с загрузки, `SIGTERM` оставляет играбельный файл. Затем проверка обрывом питания.
3. Несколько камер в записи и несколько окон сразу.
4. Подключить API к TBox Monitor и к DCL.

## Что сделано

Каркас шага 1. Отладочный APK собран (`:camd:assembleDebug`), модульные тесты прошли, пакет поставлен на ГУ `192.168.1.128` 6 ноября 2026. Стеклянное окно именно из этого приложения ещё не проверялось: руками проверялся только сам `qcarcam_test` на входе 0.

| | |
|---|---|
| Приложение | `vad.dashing.camd`, имя «Камеры ГУ», модуль `:camd` |
| Экран | выбор входа 0, 1, 3, 4, 5, 8, 9; ползунки X, Y, ширина, высота в долях экрана; «Открыть» и «Закрыть» |
| Предупреждение | у входов 4, 5, 8, 9 написано, что их держит штатный AVM. Кнопка их всё равно открывает |
| Демон | `camd-daemon.sh` в каталоге приложения. Взвод через `/sdcard/autorun.sh` и `vendor.autorun.sdcard.logfile`. Повторный взвод при живом pid выходит |
| Окно | один `qcarcam_test -config=… -seconds=86400 -nonInteractive`. Новое «Открыть» убивает предыдущий процесс. Само закроется через сутки |
| Разрешение кадра | из штатных XML: 0 — 1488×616, 1 — 1280×720, остальные из списка — 1280×800 |
| API | `127.0.0.1:8770`, одна строка запроса и одна ответа: `OPEN <id> <x> <y> <w> <h>`, `CLOSE`, `STATUS`. Ответ `OK state=…` или `ERR bad_command`. `8766` не используется: его слушает TBox MQTT |
| Загрузка | `BOOT_COMPLETED` стартует службу и API. Демон поднимается при первой команде, если выдано право записи на `/sdcard` |
| Код | `camd/src/main/java/vad/dashing/camd/` |

## Чего ещё нет

- Проверка на экране ГУ, что «Открыть» в приложении показывает картинку и что «Закрыть» её убирает.
- Сдвиг окна без перезапуска `qcarcam_test`.
- Несколько окон одновременно.
- Живой список входов с ГУ (`qcarcam_query_inputs`). Сейчас список зашит.
- Запрет открывать вход, который уже держит AVM. Сейчас только текст на экране.
- Вся запись: кодировщик, фрагментированный MP4, папка, частота кадров, предел одного файла, общий предел, ротация, тумблер «запись включена».
- Старт записи вместе с системой и дописывание файла на `SIGTERM` и при обрыве питания.
- Клиенты API в TBox Monitor и в DCL.
- Токен на API. Сейчас любой локальный процесс может открыть окно.
