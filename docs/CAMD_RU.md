# Камеры ГУ (`:camd`)

Отдельное приложение `vad.dashing.camd`. Ему отдают команды TBox Monitor и нештатный лаунчер DCL. Само оно не встроено ни в одно из них.

Факты про головное устройство: [CAMERAS_A9_RU.md](CAMERAS_A9_RU.md). Сокет `ais_server` пускает только root. Один вход камеры держит один клиент. Штатный процесс `AVMapp` уже держит входы 4, 5, 8 и 9. `avm_sharecamera` и callback SDK — уже обработанный кадр с наложенными элементами, для окон и записи его не используем. Нужен чистый кадр сенсора, буфер `qcarcam_get_frame`.

## Зачем

Сейчас нужна служба с API: TBox Monitor и DCL просят показать или убрать окно любой камеры в любом месте экрана. Картинка — чистый кадр сенсора, не `avm_sharecamera`.

Видеорегистратор отложен. Когда до него дойдёт очередь, та же служба будет кодировать те же кадры. Папка, частота, предел одного файла и общий предел настраиваются. Запись начинается вместе с системой, только если она включена, и дописывает файл при остановке. Контейнер — фрагментированный MP4: обычный MP4 пишет оглавление в конце, и обрыв питания оставляет ролик, который не открывается.

## Как устроено

Два процесса.

**Окно** — обычный процесс `vad.dashing.camd`. Он слушает `127.0.0.1:8770`, рисует по одному окну `TYPE_APPLICATION_OVERLAY` на камеру и читает последний кадр из файла. К `ais_server` он не подключается: из обычного процесса `libais_client.so` не открывается, а рисовать из `mb_daemon` эта ГУ не даёт. Порт `8765` занят TBox Monitor, `8766` — локальным статусом TBox MQTT.

**Чтение кадра** — root-программа `camd_grab`. `mb_daemon` поднимает её коротким скриптом и сразу отпускается. Программа остаётся root, открывает `libais_client.so` и `/dev/ion`, вызывает `qcarcam_get_frame` и пишет ARGB в `/data/local/tmp/camd-frame-<id>.bin`. Список нужных камер она читает из `grab.desired` в каталоге приложения. Повторный `OPEN` той же камеры файл не трогает: окно только переносится. В углу окна крестик 88 dp, он закрывает только это окно.

Для входов 4, 5, 8 и 9 тот же скрипт делает `setprop ctl.stop AVMapp` до старта клиента. Когда закрыто последнее такое окно, скрипт делает `setprop ctl.start AVMapp`.

Раскладка структур `libais_client.so` взята по символам этой ГУ (`qcarcam_get_frame` из четырёх аргументов, `qcarcam_release_frame(hndl, idx)`, версия `0x404`, цвет UYVY `0x07080102`) и по образцу, где в `p_buf` лежит fd ION. Заголовка этой библиотеки в дереве нет. На стенде без камер можно проверить, что процесс жив и `AVMapp` возвращается. Кадр проверяется только на машине.

`qcarcam_test` остаётся только в пробах. Он кадр получает, но из `mb_daemon` на экран его не кладёт: после первого кадра `qcarcam_release_frame` возвращает 13, у задней камеры `Dequeuebuffer` возвращает −38. После строки `Aborted` процесс сам не завершается: проба убивает его через 22 секунды и только потом делает `ctl.start AVMapp`.

`AVMapp` на время показа входов 4, 5, 8 и 9 должен их отпустить. `com.mengbo.avm` — только оболочка. Служба init называется `AVMapp` (`/vendor/etc/init/hw/init.JETOUR.rc`). Остановка — `setprop ctl.stop AVMapp`, возврат — `setprop ctl.start AVMapp`. Задняя передача, пока `AVMapp` остановлен и окно входа 5 ещё не открыто, в эту сборку не входит: штатная задняя картинка вернётся вместе с `AVMapp`.

## План

1. Демон и одно окно через `qcarcam_test`. Сделано как каркас. На машине картинки не даёт.
2. Пробы на машине: живой `AVMapp` и `ctl.stop AVMapp`. Сделано 10 ноября 2026, результат ниже.
3. Служба с API. Сделано в коде, на машине ещё не проверено. Несколько окон сразу: на каждую камеру не больше одного. Чистый кадр, поверх лаунчера, место и размер задаёт команда. В углу каждого окна крупный крестик. Повторный `OPEN` той же камеры переносит уже открытое окно. Для входов 4, 5, 8 и 9 служба останавливает `AVMapp`, пока открыто хотя бы одно из этих окон, и включает его снова, когда закрыто последнее. Задняя передача при остановленном `AVMapp` в эту сборку не входит.
4. Подключить вызовы API в TBox Monitor и в DCL.
5. Потом, отдельно: видеорегистратор на тех же кадрах. Фрагментированный MP4, папка, частота, предел одного файла и общий предел, старт с загрузки только если запись включена, дописывание файла на остановке.

## Пробы на машине

Нужна сборка с кнопками проб (`ProbeScripts`), не пакет от 6–7 ноября. APK: `camd/build/outputs/apk/debug/camd-debug.apk`. На стоянке, экран перед глазами:

```
adb install -r -d camd-debug.apk
```

В **Камеры ГУ** выбрать вход и нажать по очереди:

1. **Проба, AVM работает.** `AVMapp` не трогается. 20 секунд большое окно по центру (60 % экрана, не ползунки).
2. **Проба, AVM остановлен.** `setprop ctl.stop AVMapp`, те же 20 секунд, при выходе скрипта `setprop ctl.start AVMapp`. Задней картинки в эту минуту нет.

Логи в `/sdcard/Download`:

| Кнопка | Файл |
|---|---|
| AVM работает | `camd-probe-nostop-<вход>-<дата>.txt` |
| AVM остановлен | `camd-probe-stopavm-<вход>-<дата>.txt` |

`qcarcam_test` после сообщения `Aborted` сам не завершается. Проба через 22 секунды убивает его и только потом снова делает `ctl.start AVMapp`, иначе штатная камера осталась бы выключенной.

Как читать:

- Живая картинка в центре и `Average FPS` больше нуля. Чистый кадр есть. Если это было при живом AVM, отключать его не нужно.
- Картинки нет и `Average FPS: 0.00`. Кадр не пришёл. На пробе без остановки это значит, что вход занят. На пробе с остановкой — что и без AVM поток не пошёл.
- `AVMapp` снова в `ps` до конца 20 секунд второй пробы. Его перезапустили, проверка не считается.

Каркас шага 1, пробы шага 2 и служба окон шага 3. На машине проверена только проба: кадр входов 4 и 5 приходит после остановки `AVMapp`, `qcarcam_test` его на экран не кладёт. Новое окно на машине ещё не смотрели. На стенде камер нет.

## Чего ещё нет

- Проверка окна на машине. Раскладка `qcarcam_s_buffers` не сверена с этой `libais_client.so`: неверный размер структуры уронит root-процесс, экран приложения при этом останется.
- Задняя камера на задней передаче, пока `AVMapp` остановлен и окно входа 5 ещё не открыто.
- Кнопки в TBox Monitor и DCL. Сокет `127.0.0.1:8770` их команды уже принимает.
- Живой список входов с ГУ. Сейчас список зашит.
- Токен на API. Сейчас любой локальный процесс может послать команду.
- Видеорегистратор. Отложен до рабочих окон.
