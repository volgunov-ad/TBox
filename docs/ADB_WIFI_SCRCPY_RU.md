# ADB по Wi‑Fi и вывод экрана ГУ (scrcpy)

На головных устройствах Jetour Dashing с поддержкой **mbCAN** есть сервисный режим: при подключении USB‑флешки с особой структурой каталогов ГУ поднимает **ADB по TCP** (обычно порт **5555**). С ноутбука можно подключиться по Wi‑Fi и зеркалировать экран программой **scrcpy**.

Документ не про приложение TBox Monitor, а про штатный/сервисный режим самого ГУ. Нужен, в том числе, для выдачи прав ADB (см. [USER_GUIDE_RU.md](USER_GUIDE_RU.md) §1.4b) и для отладки UI.

> **Кому подходит:** ГУ линейки **Android 9 / mbCAN** (папка на флешке называется именно `mbcan`). На линейке **Android 10 / VHAL (Adayo)** этот триггер может отсутствовать или работать иначе — проверяйте на своём железе.

---

## 1. Что понадобится

| На ноутбуке | На ГУ |
|-------------|--------|
| [platform-tools](https://developer.android.com/tools/releases/platform-tools) (`adb`) | USB‑порт (Host), куда вставляется флешка |
| [scrcpy](https://github.com/Genymobile/scrcpy) | Одна сеть с ноутбуком (Wi‑Fi роутер / точка доступа телефона / хотспот ноутбука) |
| USB‑флешка, желательно **FAT32** | IP‑адрес ГУ в этой сети |

---

## 2. Подготовка флешки

1. Отформатируйте флешку в **FAT32** (на большинстве ГУ другие ФС не монтируются).
2. В **корне** флешки создайте папку:

```text
mbcan/
```

3. Внутри `mbcan` создайте **текстовый файл** без расширения (или с именем ровно `wifiport`) с содержимым — номер TCP‑порта ADB:

```text
mbcan/wifiport
```

Содержимое файла — одна строка:

```text
5555
```

Без пробелов и пустых строк вокруг числа. Порт `5555` — обычный порт `adb tcpip`; можно указать другой, тогда везде ниже подставляйте его вместо `5555`.

Итоговая структура:

```text
<корень флешки>/
  mbcan/
    wifiport          ← внутри: 5555
```

Имя папки **`mbcan`** и файла **`wifiport`** пишите латиницей, в нижнем регистре.

---

## 3. Включение ADB по Wi‑Fi на ГУ

1. Убедитесь, что ГУ **включено** и подключено к той же Wi‑Fi сети, что и ноутбук (или к хотспоту ноутбука).
2. Вставьте флешку в USB‑разъём ГУ (или в хаб, если штатный порт занят — главное, чтобы Android видел накопитель).
3. Дождитесь монтирования флешки (обычно несколько секунд). Сервис на ГУ читает `mbcan/wifiport` и запускает `adbd` в режиме TCP на указанном порту.
4. **Не вынимайте** флешку, пока работаете с ADB/scrcpy — на части прошивок режим держится, пока флешка вставлена (поведение зависит от ПО ГУ).

Узнать IP ГУ:

- настройки Android / Wi‑Fi → сведения о сети → **IP‑адрес**; или
- роутер → список DHCP‑клиентов (имя устройства часто вроде `Android` / бренд ГУ).

Пример: `192.168.1.42`.

---

## 4. Подключение ноутбука по ADB

На ноутбуке в терминале (PATH должен видеть `adb`):

```bash
adb kill-server
adb start-server
adb connect 192.168.1.42:5555
adb devices
```

Подставьте свой IP. Ожидаемый вывод:

```text
List of devices attached
192.168.1.42:5555    device
```

Если статус `unauthorized` — на экране ГУ примите диалог «Разрешить отладку по USB» (иногда появляется и для Wi‑Fi ADB). Если диалога нет и устройство `offline` — см. §6.

Проверка оболочки:

```bash
adb shell getprop ro.product.model
```

Выдача прав TBox Monitor (пример из руководства пользователя):

```bash
adb shell pm grant vad.dashing.tbox android.permission.WRITE_SECURE_SETTINGS
```

---

## 5. Зеркало экрана: scrcpy

1. Установите [scrcpy](https://github.com/Genymobile/scrcpy/releases) (Windows / macOS / Linux).
2. При уже подключённом устройстве (`adb devices` показывает `device`):

```bash
scrcpy
```

Полезные опции:

```bash
# если несколько устройств — явно указать ГУ
scrcpy -s 192.168.1.42:5555

# ограничить битрейт / разрешение (слабый Wi‑Fi)
scrcpy -b 4M -m 1024

# только просмотр без касаний с ноутбука
scrcpy --no-control
```

Управление мышью/клавиатурой с ноутбука идёт через тот же ADB‑канал. Для записи экрана: `scrcpy --record=hu.mp4`.

## 6. Типичные проблемы

| Симптом | Что проверить |
|---------|----------------|
| `unable to connect` / `Connection refused` | Флешка вставлена, структура `mbcan/wifiport` верна, порт в файле совпадает с портом в `adb connect`, ГУ и ноутбук в одной подсети, firewall ноутбука не режет исходящий TCP |
| `adb devices` пусто | `adb kill-server` → снова `adb connect IP:5555` |
| `unauthorized` | Диалог на экране ГУ; при необходимости сбросить ключи: `adb kill-server`, заново connect |
| scrcpy: `ERROR: Could not find any ADB device` | Сначала добейтесь `device` в `adb devices`, потом запускайте scrcpy |
| Тормоза / артефакты | Слабый Wi‑Fi → `-b 2M -m 800`; держите ноутбук ближе к точке доступа |
| После перезагрузки ГУ ADB пропал | Снова вставьте флешку с `mbcan/wifiport` и выполните `adb connect` |
| Флешка не читается | FAT32, не exFAT/NTFS; попробуйте другой порт/флешку |

Отключение:

```bash
adb disconnect 192.168.1.42:5555
```

После извлечения флешки TCP‑ADB на многих прошивках перестаёт слушать порт — это ожидаемо.

---

## 7. Безопасность

- Режим открывает отладочный доступ к ГУ по сети. Не оставляйте флешку с `wifiport` в автомобиле надолго и не включайте ADB в публичных Wi‑Fi.
- Порт `5555` без шифрования: любой, кто в той же сети и знает IP, может попытаться подключиться (пока не ограничено ключами авторизации ADB). После первого «Разрешить» доверяйте только своим машинам.
- Для разовой выдачи `pm grant` достаточно краткой сессии: включили → подключились → выполнили команду → вынули флешку.
