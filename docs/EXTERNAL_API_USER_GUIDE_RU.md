# Внешний HTTP API — инструкция

Практическая инструкция: как включить API на ГУ, получить токен и вызывать команды
с телефона / ПК / Tasker / Shortcuts.

Контракт и дизайн для разработчиков: [EXTERNAL_API_RU.md](EXTERNAL_API_RU.md).  
JSON действий/сигналов: [AUTOMATIONS_AI_JSON_GUIDE_RU.md](AUTOMATIONS_AI_JSON_GUIDE_RU.md).

---

## 1. Что это

TBox Monitor поднимает **локальный HTTP-сервер** в вашей Wi‑Fi / hotspot. Внешние
клиенты могут:

- читать телеметрию (`/v1/signals`);
- смотреть каталог сигналов и действий (`/v1/catalog`), в том числе RU-фразы `voiceAliasesRu`;
- выполнять действия из каталога автоматизаций (`/v1/actions/invoke`);
- запускать сохранённые правила как кнопка «Выполнить сейчас» (`/v1/automations/{id}/run`).

Сервер по умолчанию **выключен**. Без токена телеметрия и команды недоступны
(кроме `GET /v1/health`).

Типичный URL на ГУ (порт по умолчанию `8765`):

```text
http://192.168.1.128:8765/v1/...
```

Актуальные адреса смотрите в **Настройки → API** (локальный `127.0.0.1` и LAN IP).

---

## 2. Включение на ГУ

1. Откройте **Настройки → API**.
2. Включите **«Включить сервер API»**.
3. При необходимости задайте порт (обычно `8765`).
4. Убедитесь, что статус «Сервер слушает порт …» и в списке есть нужный LAN IP
   (телефон должен быть в той же сети, что и ГУ).

Проверка без токена:

```bash
curl -s http://192.168.1.128:8765/v1/health
```

Ожидается JSON с `"ok": true`, `"serverEnabled": true`.

### Простая веб-панель

Отдельный порт не нужен. Тумблер **«Простая веб-панель»** в том же разделе отдаёт
страницу управления автомобилем с уже запущенного API-сервера:

1. Включите **«Включить сервер API»** и **«Простая веб-панель»**.
2. На телефоне в той же сети откройте адрес из блока «Панель» (`http://<IP>:<порт>/`).
3. На ГУ нажмите **«Подключить приложение»**, на странице — **«Отправить запрос»**, на ГУ — **«Разрешить»**.
   Токен придёт сам и сохранится в браузере. Это тот же `pair/request` → `pair/status`, что у других клиентов.
   Ручной токен остаётся в раскрывающемся блоке «Токен вручную».
   Когда токен уже сохранён, весь блок «Подключение» свёрнут и раскрывается нажатием. Если токена нет или головное устройство его не приняло, блок открыт.

Страница раз в 2 секунды показывает температуру снаружи (ГУ, иначе TBox) и в салоне
(TBox), и даёт текущий трек любого плеера (артист, название, прогресс, предыдущий / пауза / следующий), кнопки громкости медиа (0…31, микшер ГУ; «Звук» выключает и возвращает прежний уровень), двух зон климата, синхронизации зон, режима климата (Эко / Комфорт / Сильный), скорости и направления обдува, авто-режима и обогрева/вентиляции сидений.
Язык страницы совпадает с языком программы: русская сборка отдаёт русский, английская — английский.
Запись идёт обычным `POST /v1/actions/invoke` (команды климата и `set_media_volume` — класс `safe`).
Пока тумблер выключен, `GET /` отвечает 404.

## 3. Как получить токен

Нужен заголовок:

```http
Authorization: Bearer <accessToken>
```

Два способа.

### 3.1. Создать токен вручную (для телефона / Tasker / curl)

Удобно, когда клиент **не умеет pairing** (команда в Shortcuts, Tasker, Postman, браузер).

1. **Настройки → API → «Создать токен»**.
2. Укажите имя (например «Телефон» или «Tasker»).
3. Нажмите создать — токен покажется **один раз**.
4. Скопируйте токен и сохраните на телефоне / в скрипте.
5. Клиент появится в **«Доверенные клиенты»**; отозвать можно кнопкой **«Отозвать»**.

> Токен в памяти Monitor хранится только как hash. Если закрыли окно без копирования —
> создайте новый и отзовите старый.

Пример файла токена для PC-скрипта `tools/tbox_external_api_pair.py`
(`~/.tbox_external_api_token.json`):

```json
{
  "accessToken": "вставьте_токен_сюда",
  "clientId": "manual-…",
  "clientName": "Телефон",
  "host": "192.168.1.128",
  "port": 8765
}
```

### 3.2. Сопряжение приложения (pairing)

Для приложений, которые сами умеют `pair/request` (например PC-скрипт или будущий Voice APK):

1. На ГУ: **«Подключить приложение»** (режим pairing на ~2 минуты).
2. Клиент шлёт `POST /v1/pair/request`.
3. На ГУ: **Разрешить**.
4. Клиент забирает `accessToken` через `GET /v1/pair/status`. Ответ `approved` / `denied`
   выдаётся **один раз**, следующий запрос с тем же `requestId` вернёт `404`. Неполученный
   результат хранится ~10 минут после окончания pairing.

PC:

```bash
python3 tools/tbox_external_api_pair.py
python3 tools/tbox_external_api_pair.py --check-only
```

## 4. Быстрые примеры (curl)

Подставьте IP, порт и токен:

```bash
HOST=http://192.168.1.128:8765
TOKEN='ваш_токен'
AUTH="Authorization: Bearer $TOKEN"
```

### Health (без токена)

```bash
curl -s "$HOST/v1/health"
```

### Каталог

```bash
curl -s -H "$AUTH" "$HOST/v1/catalog" | head
```

### Сигналы

```bash
curl -s -H "$AUTH" \
  "$HOST/v1/signals?ids=outside_temperature,car_speed,fuel_level_percent&source=head_unit"
```

```bash
curl -s -H "$AUTH" \
  "$HOST/v1/signals?ids=tbox_connected&source=app"
```

### Список автоматизаций

```bash
curl -s -H "$AUTH" "$HOST/v1/automations"
```

### Запуск правила (RunNow)

```bash
curl -s -X POST -H "$AUTH" -H "Content-Type: application/json" \
  "$HOST/v1/automations/f9c025e4-b8c7-4f72-b593-a2ac0e3b4102/run" \
  -d '{}'
```

Имя правила смотрите в ответе `/v1/automations` или в UI автоматизаций. Скрипт:

```bash
python3 tools/tbox_external_api_pair.py --check-only --run-automation климат
```

### Выполнить действие (safe toast)

```bash
curl -s -X POST -H "$AUTH" -H "Content-Type: application/json" \
  "$HOST/v1/actions/invoke" \
  -d '{
    "actions": [
      {
        "type": "builtin",
        "actionType": "show_toast",
        "intValue": 0,
        "stringValue": "Привет с телефона",
        "boolValue": false
      }
    ]
  }'
```

Форма любого `actions[]` — как в JSON автоматизаций (см. AI guide); список проходит ту же
проверку, что и правила (например, `delay` в допустимом диапазоне), иначе `400`. Тело запроса —
не больше 256 КБ (`413`), заголовки — не больше 32 КБ (`431`). Опасные builtin
(`adb_*` и т.п.) требуют тумблер **«Опасные команды»** в Настройки → API.

## 5. Эндпоинты (кратко)

| Метод | Путь | Токен | Назначение |
|-------|------|-------|------------|
| `GET` | `/v1/health` | нет | Жив ли сервер, `pairingActive`, версии |
| `GET` | `/` и `/panel` | нет | Страница управления автомобилем, если включена простая веб-панель |
| `POST` | `/v1/pair/request` | нет* | Начать pairing (`*` только при активном режиме) |
| `GET` | `/v1/pair/status?requestId=` | нет* | Статус / `accessToken` после approve |
| `GET` | `/v1/catalog` | да | Сигналы, действия, `voiceAliasesRu` |
| `GET` | `/v1/signals?ids=&source=` | да | Snapshot значений |
| `POST` | `/v1/actions/invoke` | да | Выполнить 1…N действий |
| `GET` | `/v1/automations` | да | Список правил (id, name, enabled) |
| `POST` | `/v1/automations/{id}/run` | да | RunNow |

Ошибки: `{ "error": { "code": "...", "message": "..." } }`.

## 6. Типичный сценарий с телефона

1. ГУ и телефон в одной сети; в Настройки → API включён сервер.
2. Создаёте токен «Телефон», копируете.
3. В Tasker / Shortcuts / HTTP-клиенте:
   - URL: `http://<IP_ГУ>:8765/v1/automations/<id>/run`
   - Method: `POST`
   - Header: `Authorization: Bearer <токен>`
   - Body: `{}`
4. Либо читаете температуру через `GET /v1/signals?ids=outside_temperature&source=head_unit`.

Готовые id правил — в ответе `/v1/automations` или в карточке правила в приложении.

## 7. Безопасность

- API слушает всю LAN: не включайте сервер в недоверенной сети без необходимости.
- Токен = полный доступ к чтению и (почти) ко всем действиям каталога; храните как пароль.
- Отозвайте неиспользуемые клиенты в Настройки → API.
- Токен, которым не пользовались больше 6 месяцев, удаляется сам через 1 минуту после запуска сервера API. Успешный запрос обновляет время; для старых записей без этой отметки считается дата создания.
- Тумблер опасных команд по умолчанию выкл.
- TLS в v1 нет (типичная домашняя/автомобильная LAN).
