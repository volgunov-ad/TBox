# Окна камер ГУ (`camd`) — инструкция для DCL

**Аудитория:** разработчик Dashing Club Launcher (`ras.dashing.tbox.launcher`).  
**Цель:** показать / убрать / переместить окно камеры на экране ГУ, командуя уже существующей службой **«Камеры ГУ»**.  
**Язык:** русский; имена пакетов, команд и полей — как в коде.

Контракт и код в этом репозитории (`preRelease`): модуль `:camd`, пакет `vad.dashing.camd`; клиент со стороны Monitor — `CamdWindowClient` / `CamdWindowWidget.kt`. Обзор инженерии: [CAMD_RU.md](CAMD_RU.md), входы AIS: [CAMERAS_A9_RU.md](CAMERAS_A9_RU.md).

---

## 0. Нужно ли что-то менять в `camd`?

| Вердикт | Что это значит для DCL |
|---------|------------------------|
| **Менять `camd` не нужно** | Контракт уже есть и им пользуется TBox Monitor. DCL может командовать так же. |
| **Опциональные улучшения** (не блокер) | Токен/allowlist на порту, push «окно закрыли крестиком/тапом», ContentProvider вместо сокета, отдельный Intent с extras вместо текстовых строк. |
| **Обязательная доработка `camd`** | Только если нужен сценарий, которого **нет** в текущем API (см. §8). Для «показать картинку камеры в заданном прямоугольнике» — **нет**. |

Итого: для DCL достаточно **клиента** к уже работающему API. Кнопки/жесты в лаунчере — работа DCL, не `camd`.

## 1. Кто есть кто

| Компонент | Пакет / модуль | Роль |
|-----------|----------------|------|
| **Камеры ГУ (`camd`)** | `vad.dashing.camd` (`:camd`) | Слушает команды, рисует оверлеи, root-grabber читает чистый кадр сенсора |
| **TBox Monitor** | `vad.dashing.tbox` | Клиент того же API (плитка, автоматизации, External API). **Не** держит картинку камеры сам |
| **DCL** | `ras.dashing.tbox.launcher` | Ещё один локальный клиент того же API |
| ~~`:camview`~~ | — | Диагностика Mengbo / `*_sharecamera`. **Не** канал для DCL |

Картинка — **чистый кадр** (UYVY через `camd_grab` → tmpfs → `TYPE_APPLICATION_OVERLAY`), не штатный обработанный AVM-превью и не `:camview`.

Платформа: **только Android 9 / mbCAN (Mengbo)**. На A10 / VHAL этого стека (`ais_server` / `AVMapp` / `mb_daemon`) в текущем `camd` нет.

## 2. Основной канал (рекомендуемый для DCL)

Это **не HTTP**. Одна TCP-сессия на localhost: **одна текстовая строка запрос → одна строка ответ → сокет закрывается**.

| Параметр | Значение |
|----------|----------|
| Хост | `127.0.0.1` |
| Порт | `8770` (`DaemonScripts.API_PORT` / `CAMD_WINDOW_PORT`) |
| Кодировка | UTF-8, перевод строки `\n` |
| Аутентификация | **нет** (любой локальный процесс может послать команду) |
| Параллелизм | сервер принимает соединения; обработка на пуле до 8 потоков `camd-api-client` |

Порты рядом (не путать):

| Порт | Кто |
|------|-----|
| `8765` | HTTP External API TBox Monitor |
| `8766` | локальный статус TBox MQTT |
| **`8770`** | **команды окон камер (`camd`)** |

### 2.1. Поднять службу, если порт молчит

Служба обычно стартует сама (`BOOT_COMPLETED`, `LOCKED_BOOT_COMPLETED` при уже разблокированном пользователе, `USER_UNLOCKED`, `QUICKBOOT_POWERON`, `MY_PACKAGE_REPLACED`). TBox Monitor при своей загрузке тоже поднимает её, если пакет установлен.

Если `connect` к `8770` даёт отказ / timeout connect:

1. Предпочтительно (как Monitor): `startForegroundService` на  
   `vad.dashing.camd` / `vad.dashing.camd.CamdService`.  
   Нужно permission **`vad.dashing.camd.permission.START`** (`protectionLevel=signature`).  
   У DCL **другая подпись** → прямой `startForegroundService` **скорее всего не сработает**.
2. Тот же signature-путь через broadcast (Monitor делает оба):  
   `sendBroadcast(new Intent("vad.dashing.camd.START").setPackage("vad.dashing.camd"))`.  
   Принимает **`StartReceiver`** (не `BootReceiver`); у отправителя тоже нужно  
   `vad.dashing.camd.permission.START`. У DCL с другой подписью этот путь **тоже** не сработает.
3. Повторять команду на `8770` с паузой ~250 мс до ~4 с (логика `CamdWindowClient.command`).

**`STATUS` службу не будит** — опрос статуса не должен вызывать старт.

Overlay: `camd` сам выставляет `appops … SYSTEM_ALERT_WINDOW allow` через root-скрипт при подготовке окна. Если права нет — ответ с `error=overlay_permission`.

## 3. Команды

Разбор: `CamdCommands.parse`. Регистр первой лексемы не важен (`OPEN` / `open`).

### 3.1. `OPEN` — показать или переместить окно

```
OPEN <id> <x> <y> <w> <h> [rotation [flipH [flipV]]] [crop=cx,cy,cw,ch] [shape=circle]
OPEN preset=<name> <x> <y> <w> <h> [shape=circle]
```

| Поле | Тип | Ограничения |
|------|-----|-------------|
| `id` | int | Известные входы: сырые `0`, `1`, `3`, `4`, `5`, `8`, `9` и штатные виды AVM **`40`–`45`** (см. таблицу ниже). **Не пишется** в preset-форме — камера берётся из пресета |
| `x`, `y`, `w`, `h` | float | Доли экрана `0…1`. Минимум стороны `0.05`. `x+w ≤ 1.02`, `y+h ≤ 1.02` |
| `rotation` | int, опционально | Целые градусы **0…360** по часовой (360 ≡ 0, нормализуется в 0); по умолчанию `0`. С `camd` ≥ **0.6.0** — любой угол; старые сборки принимают только `0/90/180/270`, прочие отвечают `ERR bad_command` |
| `flipH` | int `0\|1`, опционально | Горизонтальное зеркало картинки **после** поворота; по умолчанию `0`. Если задаёте flip — **обязателен** токен `rotation` (можно `0`) |
| `flipV` | int `0\|1`, опционально | Вертикальное зеркало; по умолчанию `0` |
| `crop=cx,cy,cw,ch` | именованный токен, опционально | Вырезка части кадра в долях `0…1`. Минимум стороны `0.05`, `cx+cw ≤ 1.02`, `cy+ch ≤ 1.02`. Префикс без учёта регистра, не более одного |
| `shape=circle` | именованный токен, опционально | Круг: картинка **вписанной окружностью** (диаметр = меньшая сторона окна, центр окна), углы и бока прозрачные. Других значений нет |
| `preset=<name>` | именованный токен | Форма пресета: **вместо** `id` и всех токенов настроек. Ровно 4 позиционных (окно). Настройки пресета клиентом не переопределяются |

**Семантика кадра (с `camd` 0.5.0):**

- **Как есть** — `OPEN <id> x y w h` без `rotation`/`flip`/`crop=`/`preset=`: кадр без поворота, зеркал и вырезки. Per-camera коррекция искажения применяется всегда (см. ниже).
- **Свои настройки** — явные `rotation`/`flip`/`crop=` поверх коррекции, как и раньше (6…9 позиционных токенов).
- **Пресет** — `OPEN preset=<name> x y w h`: поворот/зеркала/вырезка зашиты в пресет приложения «Камеры ГУ»; клиент задаёт только окно. Неизвестное имя → `ERR unknown_preset`. Смешивать `preset=` с `rotation`/`flip`/`crop=` **нельзя** (`ERR bad_command`).

Позиционных токенов: **6…9** (обычная форма) или ровно **5** (`OPEN preset=… x y w h`).

| Строка | Смысл |
|--------|--------|
| `OPEN 8 0.02 0.55 0.40 0.40` | как есть |
| `OPEN 8 0.02 0.55 0.40 0.40 90` | поворот 90° |
| `OPEN 8 0.02 0.55 0.40 0.40 0 1` | зеркало H (токен rotation обязателен, можно 0) |
| `OPEN 8 0.02 0.55 0.40 0.40 90 1 1` | поворот 90° + оба зеркала |
| `OPEN 8 0.02 0.55 0.40 0.40 crop=0.10,0.10,0.80,0.80` | вырезка центральных 80% кадра |
| `OPEN 8 0.02 0.55 0.40 0.40 shape=circle` | как есть, круглое окно |
| `OPEN preset=front_left 0.02 0.55 0.40 0.40` | пресет «перед-лево» |
| `OPEN preset=my_corner 0.02 0.55 0.30 0.30 shape=circle` | свой пресет в круге |

**Вырезка (`crop=`)** — нужен `camd` ≥ **0.4.0**. Прямоугольник задаётся в осях кадра и применяется к сэмплу последним (порядок шейдера: поворот → зеркала → линз-коррекция → тилт → crop → сэмпл); затем вырезка **растягивается на всё окно** (пропорции не сохраняются). Чёрная кромка за пределами кадра проверяется до вырезки.

**Выпрямление «рыбьего глаза» и тилт в OPEN не передаются.** Визуальная коррекция (практические k1/k2, сдвиг центра и keystone-тилт В/Г) живёт **внутри `camd`**, настраивается ползунками в приложении «Камеры ГУ», хранится **per-camera** и применяется в GLES-шейдере превью ко всем окнам и пресетам. DCL/Monitor получают уже скорректированную картинку; коэффициенты в протокол класть не нужно и не следует (это не полная калибровка Brown–Conrady).

Повторный `OPEN` того же окна **не** пересоздаёт grabber: окно только двигается/масштабируется (`state=moved`), обновляются поворот/зеркала/вырезка/форма и подтягивается актуальная коррекция из prefs.

Одно окно на камеру. Несколько разных `id` — несколько окон одновременно.

**Входы (как на машине по картинке, не по именам XML):**

| id | Название в UI | Держит штатный `AVMapp` |
|----|---------------|-------------------------|
| `8` | перед | да |
| `9` | зад | да |
| `4` | лево | да |
| `5` | право | да |
| `0` | салон / AR | нет |
| `1` | OMS | нет |
| `3` | DMS | нет |

**Штатные виды AVM (калибровка `/vendor/etc/mbhal/avm/…`, `camd` ≥ **0.8.0**):** тот же физический кадр, рисуется вендорским мешем. Списки, где есть только `0/1/3/4/5/8/9`, **неполные**.

| id | Название в UI | Физический вход | Держит `AVMapp` |
|----|---------------|-----------------|-----------------|
| `40` | сток: перед | `8` | да |
| `41` | сток: право | `5` | да |
| `42` | сток: зад | `9` | да |
| `43` | сток: лево | `4` | да |
| `44` | сток: широкий перед | `8` | да |
| `45` | сток: широкий зад | `9` | да |

Окно стока можно открыть одновременно с сырым окном той же физической камеры. На сток не действуют per-camera коррекции k1/k2/тилт. Если на ГУ нет каталога калибровки — `OK state=error error=stock_cal_missing`.

Для `4`/`5`/`8`/`9` и стоков `40`–`45` при открытии первого такого окна `camd` останавливает `AVMapp` (`setprop ctl.stop AVMapp`), пока открыто хотя бы одно; после закрытия последнего — снова `ctl.start`, если не включён режим «держать AVM выключенным».

### 3.1.1. `PRESETS` — список пресетов

```
PRESETS
```

Ответ одной строкой (нужен `camd` ≥ **0.5.0**):

```
OK presets=<камера>:<имя>:<builtin|user>,...
OK presets=none
```

Имя пресета: `^[a-z0-9_]{1,32}$`, глобально уникально. Встроенные пресеты (не удаляемые, но редактируемые в UI `camd`):

| Имя | Камера | Настройки по умолчанию |
|-----|--------|------------------------|
| `full_cabin` | 0 | полный кадр |
| `full_oms` | 1 | полный кадр |
| `full_dms` | 3 | полный кадр |
| `full_left` | 4 | полный кадр |
| `full_right` | 5 | полный кадр |
| `full_front` | 8 | полный кадр |
| `full_rear` | 9 | полный кадр |
| `front_left` / `front_right` | 8 | левая / правая половина кадра |
| `rear_left` / `rear_right` | 9 | левая / правая половина кадра |
| `left_top` / `left_bottom` | 4 | верхняя / нижняя половина, поворот 90° |
| `right_top` / `right_bottom` | 5 | верхняя / нижняя половина, поворот 270° |
| `dcl_left_blind_zone` | 9 | левая мёртвая зона (DCL), поворот 339°, flipH, своя вырезка и коррекция |
| `dcl_left_side` | 4 | левый борт (DCL), поворот 90°, почти полный кадр, своя коррекция |
| `dcl_right_blind_zone` | 9 | правая мёртвая зона (DCL), поворот 11°, flipH, своя вырезка и коррекция |
| `dcl_right_side` | 5 | правый борт (DCL), поворот 280°, почти полный кадр, своя коррекция |
| `dcl_front` | 8 | перед (DCL), вырезка и коррекция как у откалиброванного `full_front` |
| `dcl_rear` | 9 | зад (DCL), flipH, вырезка и коррекция как у откалиброванного `full_rear` |

Пользовательские пресеты создаются в приложении «Камеры ГУ» и меняют настройки только там. Коррекция для пресет-открытия: по умолчанию применяется текущая коррекция камеры-источника (таблица входов выше, `k1/k2/центр/тилт` — на момент `OPEN`); в редакторе пресета переключатель «Коррекции изображения по умолчанию» позволяет закрепить за пресетом собственные значения коррекции — тогда правки коррекции камеры на это окно не влияют. В протоколе это никак не отражается: клиент по-прежнему шлёт только `preset=` и окно.

### 3.2. `CLOSE` — закрыть

```
CLOSE <id>     # одно окно
CLOSE          # все окна
```

### 3.3. `AVM` — удерживать штатный круговой обзор выключенным

```
AVM ON    # или AVM 1 — держать AVMapp остановленным (в т.ч. после reboot prefs)
AVM OFF   # или AVM 0 — закрыть ВСЕ открытые окна camd и сразу запустить AVMapp
```

**Важно:** `AVM OFF` — это не «только разрешить штатный 360 снова». Служба **закрывает все** окна (`OPEN` сырые и сток 40–45), сбрасывает `keep_avm`, затем стартует `AVMapp`. Если клиенту нужно лишь убрать удержание AVM, но оставить свои оверлеи — такого отдельного режима нет: сначала `CLOSE`/`CLOSE <id>` по ненужным окнам, либо смириться с полным закрытием. Пока идёт запись регистратора, обе команды отвечают `error=recorder_active`.

В `STATUS` флаг: `keep_avm=0|1`.

### 3.3.1. `REC` — регистратор

Тот же стиль, что `AVM ON|OFF` (SET). GET enabled — поле `rec_enabled=` в `STATUS`, отдельно от «запись идёт».

```
REC ON    # или REC 1 — включить мастер-переключатель (папка/камеры уже в prefs camd)
REC OFF   # или REC 0 — выключить и остановить запись
REC SOS   # или REC SAVE — аварийное сохранение (camd ≥ 0.8.6, см. ниже)
```

Ответы: `OK state=rec_on enabled=1` / `OK state=rec_off enabled=0`, либо
`OK state=error error=no_cameras|no_folder`.

**`REC SOS` — аварийное сохранение (camd ≥ 0.8.6).** Мгновенно закрывает текущие сегменты
всех пишущих камер (moov пишется за ~50 мс, запись продолжается новым сегментом) и копирует
их вместе с предыдущими файлами (количество — настройка в UI `camd`, 0–5, общая для камер)
в подпапку `sos_<метка времени>` папки аварийного сохранения. Копии ротацией квоты не удаляются.
Папка сохранения и «предыдущих файлов» настраиваются только в UI `camd` — в протоколе их нет.

Ответы: `OK state=rec_sos started` (копирование запущено; результат — в сообщении UI `camd`),
`OK state=rec_sos busy` (предыдущее сохранение ещё идёт), ошибки:
`OK state=error error=rec_off` (запись не идёт — сохранять нечего),
`OK state=error error=no_sos_folder` (папка сохранения не выбрана в UI).

**Не путать:**

| Поле / смысл | Что это |
|--------------|---------|
| `rec_enabled` | мастер-переключатель (`REC ON`, переживает reboot) |
| `rec_active` | сегменты сейчас пишутся на носитель (`enabled`, но нет носителя → `0`) |
| `rec_sos` (camd ≥ 0.8.6) | аварийное сохранение выполняется прямо сейчас |
| `rec_seg` (camd ≥ 0.8.6) | длина сегмента в секундах (30/60/180/300, по умолчанию 180) |

Их **нельзя** склеивать в один status-blob.

### 3.4. `STATUS`

```
STATUS
```

Пример ответа:

```
OK windows=8,4 avm=stopped keep_avm=0 rec_enabled=0 rec_active=0 rec_sos=0 rec_seg=180
OK windows=none avm=running keep_avm=1 rec_enabled=1 rec_active=1 rec_sos=0 rec_seg=180
```

`rec_sos=` и `rec_seg=` появились в 0.8.6; на старых сборках их нет — парсите по префиксам, а не по фиксированному числу полей.

## 4. Ответы и ошибки

Формат: `OK …` или `ERR …` (одна строка).

| Ответ / фрагмент | Смысл |
|------------------|--------|
| `OK state=open input=<id>` | Окно открыто |
| `OK state=moved input=<id>` | То же окно перенесено |
| `OK state=closed …` | Закрыто |
| `OK state=avm_held` / `OK state=avm_restore` | Переключатель AVM |
| `OK state=rec_on enabled=1` / `OK state=rec_off enabled=0` | Переключатель регистратора |
| `OK state=rec_sos started` / `OK state=rec_sos busy` | Аварийное сохранение (0.8.6+) |
| `OK windows=… avm=… keep_avm=… rec_enabled=… rec_active=… rec_sos=… rec_seg=…` | Статус (все поля раздельные; `rec_sos`/`rec_seg` только на 0.8.6+) |
| `ERR bad_command` | Строка не разобралась / неверные числа / неизвестный id / геометрия вне правил |
| `ERR no_windows` | Служба без слоя окон (не должна встречаться в нормальном FGS) |
| `OK state=error error=overlay_permission` | Нет права оверлея у `vad.dashing.camd` |
| `OK state=error error=unknown_input` | Неизвестный id (на практике парсер обычно уже отсечёт → `ERR bad_command`) |
| `OK state=error error=mb_daemon не ответил` / `камера не запустилась…` | Root-grabber / `mb_daemon` не поднял кадр |
| `OK state=error error=overlay_timeout` | UI-поток не успел добавить View за 3 с |

Клиент Monitor считает ошибкой любую строку, начинающуюся с `ERR` **или** содержащую `state=error`.

Сетевые: `Connection refused` / connect timeout → служба не слушает (разбудить, §2.1). Read timeout при живом grabber — отдельно: команда уже принята, но операция долгая (Monitor для команд ждёт до ~20 с).

## 5. Последовательность для DCL

Типичный сценарий «показать переднюю камеру внизу слева»:

1. Убедиться, что установлен пакет `vad.dashing.camd` (иначе API нет).
2. (Опционально) `STATUS` — если connect отказал, **не** считать это фатальным для показа.
3. Отправить  
   `OPEN 8 0.0200 0.5500 0.4000 0.4000 0`  
   (2 % / 55 % / 40 % / 40 % — дефолт плитки Monitor).
4. Если connect отказал → broadcast `vad.dashing.camd.START` → повторить `OPEN` до ~4 с.
5. Разобрать ответ: успех только без `ERR` и без `state=error`.
6. Скрыть: `CLOSE 8` или `CLOSE`.

Поток: **не UI-thread** (блокирующий socket + возможное ожидание старта). Оверлей добавляется внутри `camd` на main looper; клиенту ждать только строку ответа.

Жизненный цикл:

- Окно живёт в процессе `camd`, не в DCL. Уход HOME / смена Activity лаунчера окно само не закрывает.
- Крестик 88 dp в углу окна закрывает только это окно внутри `camd`. DCL об этом **не уведомляется** (push нет).
- Убить процесс `camd` / `force-stop` — окна исчезнут; службу нужно снова поднять.

## 6. Примеры

### 6.1. Kotlin / Java (сокет), как Monitor

```kotlin
fun camdCommand(line: String, connectMs: Int = 1500, readMs: Int = 20_000): String {
    Socket().use { socket ->
        socket.connect(InetSocketAddress("127.0.0.1", 8770), connectMs)
        socket.soTimeout = readMs
        socket.getOutputStream().apply {
            write("$line\n".toByteArray(Charsets.UTF_8))
            flush()
        }
        return socket.getInputStream().bufferedReader().readLine().orEmpty()
    }
}

// открыть переднюю
camdCommand("OPEN 8 0.0200 0.5500 0.4000 0.4000 0")
// закрыть
camdCommand("CLOSE 8")
```

Разбудить службу (без signature permission):

```kotlin
context.sendBroadcast(
    Intent("vad.dashing.camd.START").setPackage("vad.dashing.camd")
)
```

### 6.2. adb / shell smoke

```bash
# если есть toybox/nc на ГУ:
printf 'STATUS\n' | nc 127.0.0.1 8770
printf 'OPEN 8 0.1 0.1 0.3 0.3 0\n' | nc 127.0.0.1 8770
printf 'CLOSE 8\n' | nc 127.0.0.1 8770
```

### 6.3. Альтернатива: через TBox Monitor External API

Если DCL уже ходит в Monitor (`content://vad.dashing.tbox.localaccess` → Bearer → `http://127.0.0.1:<port>/v1/...`), можно не трогать `8770` напрямую:

`POST /v1/actions/invoke` (класс `confirm`, базовый токен достаточно):

```json
{
  "actions": [
    {
      "type": "builtin",
      "actionType": "camd_window",
      "intValue": 8,
      "stringValue": "open 2 55 40 40 0",
      "boolValue": false
    }
  ]
}
```

| Поле | Значение |
|------|----------|
| `actionType` | `camd_window`, `camd_keep_avm` или `camd_recorder` |
| `intValue` (`camd_window`) | id камеры (в preset-режиме используется для `CLOSE`, сам OPEN берёт камеру из пресета) |
| `stringValue` (`camd_window`) | `open <x%> <y%> <w%> <h%> [rotation [flipH [flipV]]] [crop=x%,y%,w%,h%]`, `open preset=<имя> <x%> <y%> <w%> <h%>`, суффикс ` shape=circle` — **в процентах 0…100**, либо `close` / `close_all` |
| `boolValue` (`camd_keep_avm`) | `true` = `AVM ON`, `false` = `AVM OFF` |
| `boolValue` (`camd_recorder`) | `true` = `REC ON`, `false` = `REC OFF` |
| Сигналы | `camd_recorder_enabled`, `camd_recording_active` (`on`/`off`) |

Monitor сам переводит проценты в доли и шлёт строку на `8770`, при необходимости будит службу.  
Это **обёртка**, не отдельный протокол камер. Прямой сокет проще и не требует consent/токена.

## 7. Окно на экране (факты реализации)

| Свойство | Значение |
|----------|----------|
| Тип окна | `WindowManager.LayoutParams.TYPE_APPLICATION_OVERLAY` |
| Флаги | `FLAG_NOT_FOCUSABLE`, `FLAG_NOT_TOUCH_MODAL`, `FLAG_LAYOUT_IN_SCREEN` |
| Координаты | от `(0,0)` реального дисплея; `x/y/w/h` — доли × `getRealMetrics` |
| UI | `SurfaceView` + шейдер UYVY (поворот, flip, визуальная коррекция + keystone-тилт, crop, опциональный вписанный круг с прозрачными углами при `shape=circle`), подпись «жду кадр»; крестик ✕ и закрытие тапом по окну — опции пользователя во вкладке «Настройки» `camd` (крестик по умолчанию включён, тап — выключен; применяются к открытым окнам сразу), фон окна чёрный в прямоугольном режиме и прозрачный в круглом |
| Кадр | root `camd_grab` → `/mnt/camd-ram/camd-uyvy-<id>`; процесс приложения к `ais_server` не коннектится |
| OEM 360 | штатный UI (`com.mengbo.avm` / `AVMapp`) при открытии surround-входов останавливается; это не окно DCL и не «красивый» undistort OEM |

## 8. Что DCL может сегодня vs чего нет

### Можно сегодня

- Открыть / переместить / закрыть любое из 7 известных окон.
- Несколько камер сразу.
- Три режима кадра: **как есть** (простая строка 6 токенов), **свои настройки** (поворот/зеркала/вырезка поверх коррекции), **пресет** (`preset=<имя>` — настройки задаёт «Камеры ГУ», клиент не меняет).
- Опциональные зеркала `flipH` / `flipV` (нужен `camd` ≥ **0.3.0**; старые клиенты без токенов — без зеркал).
- Опциональная вырезка `crop=` (нужен `camd` ≥ **0.4.0**; старые службы ответят `ERR bad_command` — не слать crop на старую службу).
- Круглая форма окна `shape=circle` (нужен `camd` ≥ **0.5.0**) — вписанная окружность, углы прозрачные.
- Список пресетов `PRESETS` (нужен `camd` ≥ **0.5.0**): встроенные имена фиксированы (таблица в §3.1.1), пользовательские — как создали в приложении.
- Визуальная коррекция превью (k1/k2, центр, keystone-тилт В/Г) — **в UI `camd`**, без токенов OPEN; действует для всех клиентов сразу.
- Узнать статус (`windows`, `avm`, `keep_avm`, `rec_*`).
- Удерживать штатный AVM выключенным (`AVM ON`/`OFF`).
- Регистратор: включить/выключить запись (`REC ON`/`OFF`, camd ≥ 0.8.2) и выполнить аварийное сохранение (`REC SOS`, camd ≥ 0.8.6).
- Разбудить службу broadcast’ом `vad.dashing.camd.START`.
- То же через Monitor `camd_window` / `camd_keep_avm` / `camd_recorder`, если уже есть локальный API-доступ.

### Совместимость OPEN

| Клиент → служба | Поведение |
|-----------------|-----------|
| Старый OPEN (6/7 токенов) → новый `camd` | OK; с 0.5.0 это режим «как есть» (дефолтной вырезки из UI больше нет) |
| Новый OPEN с flip (8/9) → старый `camd` (только 6/7) | `ERR bad_command` — не слать flip на старую службу |
| OPEN с `crop=` → `camd` < 0.4.0 | `ERR bad_command` — не слать crop на старую службу |
| OPEN с `shape=circle` → `camd` < 0.5.0 | `ERR bad_command` — не слать shape на старую службу |
| OPEN с `preset=` → `camd` < 0.5.0 | `ERR bad_command` — не слать preset на старую службу |
| OPEN с `rotation` вне 0/90/180/270 (например `45`) → `camd` < 0.6.0 | `ERR bad_command` — произвольные углы только на свежие сборки |
| `preset=` с неизвестным именем → `camd` ≥ 0.5.0 | `ERR unknown_preset` |
| `PRESETS` → `camd` < 0.5.0 | `ERR bad_command` |
| `REC SOS` → `camd` < 0.8.6 | `ERR bad_command` — не слать SOS на старые сборки |
| Monitor / рекомендация DCL | не слать `rotation`/`flip`/`crop=`, если кадр «как есть»; если есть flip — всегда писать `rotation` (хотя бы `0`); пресет вызывать только именем, окно — отдельно |

### Нет в контракте (потребует доработки `camd` или другого стека)

| Запрос | Статус |
|--------|--------|
| Intent/ContentProvider «камера» внутри **TBox Monitor** (без `camd`) | **нет** — Monitor только клиент |
| HTTP на `8770` | **нет** — текстовый TCP line protocol |
| Токен / ограничение только пакетом DCL | **нет** (сейчас открыто для localhost) |
| Событие «пользователь нажал ✕» в DCL | **нет** |
| Живой список входов с ГУ | **нет** — список зашит |
| A10 / VHAL камеры тем же API | **нет** |
| Калибровочные k1/k2 / intrinsics в OPEN | **нет** — правка только в UI `camd`; не полная модель объектива |
| Полный OEM UI «Камера 360» / обработанный AVM-превью | **нет** — `camd` даёт сырой кадр; штатная оболочка `com.mengbo.avm` / процесс `AVMapp` — отдельный стек (см. [CAMERAS_A9_RU.md](CAMERAS_A9_RU.md)) |
| Гарантия кадра на всех машинах | окно на стенде/машине ещё доводится; API команд уже в коде |
| Задняя картинка на R, пока `AVMapp` остановлен и окно `5`/`9` ещё не открыто | **не входит** в текущую сборку |
| Управление папкой/камерами/квотой/длиной сегмента регистратора и настройками SOS по API | **нет** — переключатель `REC ON/OFF`, `REC SOS` и `STATUS` есть, настройки только в UI `camd` |
| Запуск восстановления битых роликов по API | **нет** — кнопка «Восстановить битые» только в UI `camd` (0.8.7) |

### Опциональные niceties (не обязательны для первой интеграции DCL)

- Signature shared / выдача `vad.dashing.camd.permission.START` DCL — чтобы будить FGS так же, как Monitor (сейчас хватает broadcast).
- Auth на порту, если появятся недоверенные APK на ГУ.
- Callback/broadcast при `CLOSE` с крестика.

## 9. Чеклист интеграции DCL

1. На ГУ установлен `vad.dashing.camd`; для `preset=` / `shape=circle` / `PRESETS` нужна сборка **≥ 0.5.0**, для `REC SOS` — **≥ 0.8.6** (старые ответят `ERR bad_command` — см. таблицу совместимости).
2. Клиент пишет одну строку на `127.0.0.1:8770` с фонового потока.
3. При `Connection refused` — `vad.dashing.camd.START` + retry; `STATUS` не использует для пробуждения.
4. Геометрию лучше нормализовать на стороне клиента (как Monitor: проценты → доли, окно внутри экрана, сторона ≥ 5 %).
5. Не смешивать с `:camview` и не ждать ContentProvider камер у Monitor.
6. Учитывать побочный эффект: открытие surround-входов гасит штатный `AVMapp`, пока окна открыты (или пока `keep_avm=1`).
